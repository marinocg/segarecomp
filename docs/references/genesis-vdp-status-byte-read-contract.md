# Genesis VDP status BYTE reads (SEG-021-T037)

Sources consulted 2026-09-27:

- Sega Enterprises, *Genesis Technical Overview* v1.00 (1991), [primary PDF](https://ia801909.us.archive.org/24/items/Genesis_Technical_Overview_v1.00_1991_Sega_US/Genesis_Technical_Overview_v1.00_1991_Sega_US.pdf), pp. 18–20, §4 “VDP PORT”: the CONTROL-port read exposes a 16-bit status word with an upper D15–D8 lane and lower D7–D0 lane; VB is bit 3. The instruction to use WORD/LONG access applies when **setting** VDP registers, not to reading status. This manual does not specify an exact open-bus value for unused high bits or cycle-accurate values of dynamic status flags.
- Eke-Eke, [Genesis Plus GX `core/mem68k.c`, `vdp_read_byte` CTRL cases](https://github.com/ekeeke/Genesis-Plus-GX/blob/master/core/mem68k.c) and [the `vdp_68k_ctrl_r` function in `core/vdp_ctrl.c`](https://github.com/ekeeke/Genesis-Plus-GX/blob/master/core/vdp_ctrl.c): the even BYTE lane selects the high byte and the odd BYTE lane selects the low byte of a status transaction; both call the common status reader. That reader clears its control-command `pending` flip-flop and collision/overflow flags but does not acknowledge the 68000 V-interrupt or clear the realtime VB bit. This is corroborating emulator implementation, **not** an independent measurement of Genesis hardware timing. Its upper unused bits come from prefetched/open-bus data, outside this project's model. No emulator code is copied.

## Bounded runtime policy

`genesis_vdp_access` owns the status selector: WORD read at the control-port base returns `status_register`; BYTE reads at its even and immediately following odd addresses return respectively `(uint8_t)(status_register >> 8)` and `(uint8_t)status_register`. Each success samples one full word, clears `control_port_awaiting_second_word` and `control_port_first_word` (not the already-applied address/code state), and increments `vblank_status_read_count` once. The existing synthetic interrupt compatibility policy tests **bit 3 of the full snapshot**, including for the high-byte read; it raises `vblank_pending` and increments transitions only on a false-to-true pending change. A status read does not clear sticky pending or VB. There is no new collision/overflow, DMA timing, FIFO, or open-bus model: unused upper bits come from the existing deterministic `status_register` field. This is a **replaceable project compatibility policy**, not a claim that real hardware returns zero on undriven upper bus bits.

The second CONTROL-port mirror, LONG status reads, odd-aligned WORD reads, DATA/HV reads, and BYTE control-port writes remain unsupported under existing routing rules. Synthetic direct-runtime tests exercise both BYTE lanes, existing WORD behavior, latch clearing, count and transition cardinality, malformed neighboring selectors, and deterministic replay.
