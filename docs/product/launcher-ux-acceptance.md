## Rendering contract (from T001, unchanged by T010)

- Text is rasterized by Dear ImGui 1.92's dynamic font system from real Inter Regular and Inter SemiBold faces (`AddFontFromFileTTF`; SIL OFL 1.1, release 4.1) plus Silkscreen Bold for headings. There is no faux bold and
  no whole-window intermediate texture.
- The SDL3 backend reports `io.DisplayFramebufferScale` = the window's pixel density every frame; ImGui derives the glyph raster density from it (`FontRasterizerDensity`), so a Retina or 200 % window rasterizes glyphs at
  2x and draws them at logical size (texels map 1:1 to pixels). `FontScaleDpi` stays 1.0 on purpose: text is sized in explicit logical pixels (`ctx.u()`) and must not be scaled twice.
- After `ImGui::Render` the renderer scale is set to output size / window size, so logical units map to physical pixels; the SDL_Renderer backend then does not scale clip rectangles a second time.
- Layout scale `S` = OS display scale / pixel density (Windows fractional scaling: density 1, `S` = scale; macOS Retina: density 2, `S` = 1) times the compact factor.
- A missing font file falls back to ImGui's embedded face (regular) and to the regular face (bold): proven in T010 on an installed package copy with both Inter files removed (layout intact, thinner glyphs; `screenshots/launcher-ux/t010-font-fallback-1to1.png`).
- `SEGARECOMP_SHOT_SCALE` is a logical layout aid, not physical HiDPI evidence.

### Corrective round A (F30): data integrity of the move and of the old-location cleanup

Findings (reproduced first with the smallest synthetic fixtures in `data_location_test`; before the fix 26 checks failed):

* **P1-1 same-size source change undetected.** Reproduced: the `after_copy` hook rewrites the source save (64 bytes -> 64 other bytes), the source catalog (same length) and adds a file to a durable folder after it was copied; the move completed and switched (failures `same-size save change`, `same-size catalog change`, `file added during the move`). Fixed: before the commit every planned source file is hashed again and compared with the digest taken before it was copied (the catalog's source against what was rebased; its destination copy is hashed before the rebase), the source's durable file set is scanned again, and any difference is `source_changed` with rollback (bootstrap never written, destination removed, old library authoritative). A different-length catalog change was already caught by the size check.
* **Multi-process.** The in-process busy guard cannot see a second launcher. Each process now registers `<bootstrap>.instances/<pid>`; the move and the cleanup refuse with the typed `other_instance_running` (plain text and "Close the other Segarecomp window") while a live foreign marker exists; stale markers are ignored. Guarantee and limits: ADR 0317 section 6. Headless commands register too when they resolve the roots from the bootstrap pointer (the same call); a process started with `SEGARECOMP_CACHE_DIR` set does not register (round C: stated limit, ADR 0317 section 6).
* **P1-2 the original catalog could be deleted on a weak check.** Reproduced: a non-empty invalid JSON, a JSON object that is not a catalog, a JSON array, a catalog naming a missing managed ROM, and a catalog naming a missing cover all let the old catalog be offered and removed. Fixed: the destination catalog is loaded on a temporary copy with the existing loader (must be `loaded`, every record readable) and its managed references must exist; checked in the plan and again immediately before the original is removed; a file the new catalog still references at the old root is kept. A legitimately updated catalog is still accepted.
* **P2 library-only override.** `SEGARECOMP_LIBRARY_DIR` (and `SEGARECOMP_CACHE_DIR` / `SEGARECOMP_HOME`) equal to or inside the old root, under any spelling, now refuses in the core, in the plan and the run (`library_active`, `old_root_active`, `home_active`), with plain text; the Settings cleanup screen maps these through `cleanup_refusal_text` like the existing ones.

Tests (all in `data_location_test`, exit 0): `test_source_changed_same_size_is_detected`, `test_cleanup_validates_destination_catalog`, `test_cleanup_revalidates_before_delete`, `test_cleanup_refuses_active_environment`, `test_other_instance_blocks_move_and_cleanup` (a real second process via fork: refused, nothing changed, stale marker ignored, allowed after it exits), `test_instance_started_during_move` (second process appears mid-move: the pre-commit re-check rolls back), `test_plain_text_for_every_reason` (extended). ## Final cleanup safety pass (F30)

Two gaps in `run_old_root_cleanup` (the plan was treated as authorization) and one parsing hazard were closed.

- **P1-a (reproduced)**: an original whose content changed (same size) between plan and deletion, or a destination copy changed after planning, was still deleted. Pre-fix failing checks in `test_cleanup_final_revalidation`: "A: the changed original is preserved", "A: a specific reason is reported", "A: the record is retained...", "B: the original is preserved", "B: a specific reason is reported", "B: the record is retained".
- **P1-b (reproduced)**: the destination catalog could start referring to an old managed file, or become unreadable, after planning; the run did not recheck. Pre-fix failing checks: "C: the file the new catalog now refers to is kept" (ROM and cover variants), "C: reason reported", "D: managed originals survive an unreadable new catalog", "D: reason reported".
- **Fix** (`data_location.cpp`, `run_old_root_cleanup`): the manifest is read once per run; immediately before each `migrated_copy` removal (after `before_remove`) the run re-checks that the original is an ordinary file inside the old root, the new copy is a separate unlinked file (`new_copy_doubt`), original size+SHA-256 equal the manifest entry, the new copy equals the manifest entry (except the intentionally rewritten `library/library.json`, validated structurally), and recomputes the CURRENT destination catalog's references: a referenced old file is kept, and an unreadable/invalid catalog keeps every managed file. Each refusal preserves the original and adds a specific entry to `res.problems` ("the original changed since it was verified", "the new copy differs...", "the new catalog now refers to it", "the new catalog cannot be read"); the journal stays when anything remains. The eligible set is not broadened; regenerable directories are unchanged. Reasons appear in the existing problems list of the cleanup result; no UI text was added or changed, so no new screenshot was taken.
- **P2 (partly reproduced)**: `foreign_instance_running` used `std::stoll`. `all_digits` already limits names to 18 digits, so no exception was reproducible; the real defect was that digit names that are not valid pids (`0`, `00`, 11-digit numbers) were treated as dead pids and deleted (failing: "uninterpretable marker kept: 0 / 00 / 99999999999", "no live foreign instance..."). Now `parse_marker_pid` (`std::from_chars`, at most 10 digits, 1..INT32_MAX, no throw) is used and unparseable names are ignored and left in place.
