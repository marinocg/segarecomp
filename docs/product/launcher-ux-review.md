## T001: text rendering (SEG-150-T001)

### Audit result (pinned SDL 3.4.16, Dear ImGui 1.92.9b, SDL_Renderer backend)

- The SDL3 backend reports `io.DisplayFramebufferScale` = window pixel density each frame; Dear ImGui 1.92 derives the glyph raster density from it automatically (`g.FontRasterizerDensity`). `FontScaleDpi` stays 1.0 on purpose: the launcher sizes text in explicit logical pixels (`ctx.u()`), so it must not be multiplied a second time.
- `SDL_SetRenderScale(output / window size)` after `ImGui::Render` makes logical units map to physical pixels. The SDL_Renderer backend then uses a clip scale of 1 when the renderer scale is not 1, so clipping is not scaled twice. The glyph atlas is baked at the framebuffer density and drawn at the same scale: texels map 1:1 to pixels. There is no whole-window intermediate texture.
- Layout scale `ctx_.S` = OS display scale / pixel density (Windows fractional scaling: density 1, S = scale; macOS Retina: density 2, S = 1) times the compact factor. This remains the contract; it was not changed.
- Measured defects (fixed): the body face was Dear ImGui's embedded thin vector font, and "bold" was that same face drawn twice with a 0.6 px offset (smeared stems, wider measured text than the drawn text). Now: Inter Regular and Inter SemiBold (real faces, SIL OFL 1.1, unmodified static TTFs of release 4.1) via `AddFontFromFileTTF`; the double draw and its 0.6 px measurement fudge are gone. Silkscreen Bold stays for headings only. A missing font file falls back to the embedded face (regular) and to the regular face (bold).
- Not changed: filtering (covers filtered, pixel art nearest), FreeType (not evaluated; the SDL_Renderer/stb_truetype result is already clean at 1:1), atlas handling.

### Known limits

- Inter covers Latin, Greek and Cyrillic; CJK and other scripts are not in the bundled faces (the embedded vector face had the same limit). Non-Latin file names in those scripts show fallback glyphs. A merged fallback face is a later decision, not added here to avoid a large font.
- Glyph-boundary ellipsis uses the same measurement as drawing (`CalcTextSizeA`), so truncated labels end on whole glyphs.

## T008: data location storage contract (SEG-150-T008)

Core contract and tests only; no UI and no screenshots (the Settings control is T009). The Storage & Data "Where things live" card from T007 stays read-only until then. Decision record: ADR 0317.

Contract: durable data (catalog, settings, BIOS profile store, covers, managed ROM copies, mods and their packages, saves, recordings, Sega CD backup RAM and recordings) migrates by copy, verification (counts, sizes, SHA-256) and an atomic pointer-file switch; builds, compiler cache, downloads and the catalog backup are regenerable and stay behind (those games rebuild); external ROM/BIOS/CUE files are never moved or rewritten; only references to managed copies are rebased, in the copy of the catalog. An environment override refuses the move and names the effective path. The old folder is never changed or removed by the migration; its cleanup is a separate explicit core operation. A crash is recovered at the next start: before the switch the old folder stays authoritative and only what the journal created is removed; after the switch the new folder is authoritative.

Evidence (synthetic trees only): `data_location_test` (bootstrap read/write/precedence, upgrade no-op, plan classes, environment refusals, success with hashes and restart, external files untouched, every destination refusal, concurrent build/game/maintenance, space, permission bits, symlink escapes, crash at copy / rebase / verify / before and after the switch with recovery, corrupted copy, source changed mid-copy, cancellation at three points, damaged and newer journal, journal owned by a live process, double migration, old-root cleanup that removes only regenerable items and unchanged verified duplicates), `launcher_data_location_test` (the real headless launcher honours a pointer file, falls back for an unavailable or damaged one, and lets the environment win).

Not verified: Windows and macOS path behaviour (case-insensitive aliases, `/tmp` links, drive letters), an OS-level permission denial while copying (as root the refusal comes from the permission bits), very large libraries (the plan refuses above 100000 files), the UI.
