# ADR 0235: SEG-102-T004 - focused hardware and differential tests of the PCM pointer model (M6)

- Status: Accepted. Milestone SEG-102 (M6), task T004. Gate `PCM_DIFFERENTIAL_GO`.
- Related: ADR 0233 (specification), 0234 (implementation).

## What was added

- `tests/sega_cd_pcm_test.c` (CTest `sega_cd_pcm_test`, labels `fast`, `full`): a real `ScdMachine` driven through the sub bus (`scd_read`/`scd_write` at `$FF0000-$FF7FFF`, so /LDS lane, mirroring and the typed stop are exercised on the real path) with the machine instant set explicitly. Three layers of expectation:
  1. **Closed-form rows**, derived by hand and independent of the per-event stepping: after n events a channel at start page `st` with step `fd` is at `st x 2^19 + n x fd` modulo 2^27; rows for reset defaults, a disabled chip, a zero step, half-byte and 1.875-byte (fractional) steps, a 16-bytes-per-event step through the 64 KiB wrap, several channels, an exactly-on / one-cycle-before / one-cycle-after sample event, START while ON and while OFF, ON/OFF reload and resume, channel selection ownership of the registers, the loop marker (period-4 pattern over 20 events), an immediate marker at the loop start, a marker written during activity, a marker in another bank, the peripheral reset (re-anchoring at an instant off the old grid), word and byte reads, the 1 MiB and 16 KiB mirrors, the even-lane byte write drop, and every refused read class (ENV, CTRL, ON/OFF, an illegal register, `$20`, `$7F`, wave RAM first and last byte, the even-address byte read) including that a refused read neither synchronizes nor enters the device log.
  2. **Differential vectors against the reference's chip code** (`tests/sega_cd_pcm_vectors.inc`, 6 seeded sets, 822 pointer reads, 2,000+ register and wave RAM writes, half with `$FF` loop markers, half with large steps, access instants spread over 0-20,000 sub cycles with a fifth placed on a sample boundary +-1): the sequences were generated by a project-authored driver feeding the pristine Genesis Plus GX `pcm.c` (consulted behavioural reference; none of its code is in the repository) and every read value recorded. The test replays them under both clock profiles (BIOS-image line-locked and synthetic exact) and requires every read equal. A first generator version double-evaluated a macro argument, so the printed operations did not match the executed ones; the mismatch was found by the first run, the generator fixed, the vectors regenerated and the results above are from the corrected generator only.
  3. **Partition independence**: the same sequences with extra synchronizations at arbitrary instants (what a different deadline partition causes) give identical reads and states (97- and 1,000-cycle step).
- `tests/sega_cd_pcm_native_test.py` (CTest `sega_cd_pcm_native_test`) with the project-authored generated-native fixture `pcm` (`tools/sega_cd_fixture_disc.py`): RES0 = 0 restarts the chip at time 0, channel 0 is started by an ON write at 100 sub cycles and read as a byte, as the high byte and as a word at instants derived **from the MC68000 cycle table only** (exactly on an event, 4 cycles before one, 4 cycles after one). The six values the CPU receives (9, 0, 10, 19, 29, 40) equal the hand-derived ones; the `--pcm-trace` log is checked against a second, closed-form oracle written in the test (events in [ON write, read)); two process runs, three slice sizes and eight slice seeds give identical reports **and** identical traces.
- `tests/sega_cd_pcm_replay.c` (built on request, not a registered test): replays a recorded PCM operation sequence through the product model and counts the pointer reads that differ. The recordings of authentic runs stay private.

## Results

- All checks of `sega_cd_pcm_test` and `sega_cd_pcm_native_test` pass; they also pass with the runtime and the test compiled `-fsanitize=address,undefined -fno-sanitize-recover=undefined`.
- **Not a constant stub.** The vector reads cover 60+ distinct values; the closed-form rows distinguish step counts and boundary positions. Mutation check (each applied alone to `scd_pcm.c`, test re-run): floor instead of ceil in the event count, `+period` instead of `+period-1`, a loop reload that also steps, ON/OFF polarity reversed, a write that reloads an ON channel, a reset that does not re-anchor, advancing with the chip disabled - **all detected** (28, 28, 12, 72, 25, 1 and 35 failures); the 27-bit mask widened to 28 bits is not detected because it is unobservable (bit 27 never reaches the wave address or a pointer read) - an equivalent mutant.
- **Authentic operation sequences.** The reference's own PCM operation streams of the two authentic routes (variant F of ADR 0233: R0 3,376,658 operations, R1 153,973), including 584,177 and 153,883 register and wave RAM writes and the two chip resets, replayed through the product model: **2,792,481 of 2,792,481 R0 pointer reads and 88 of 88 R1 pointer reads equal** (largest single catch-up 1,348,392 sample events). The same replay with the loop reload also stepping (the other public implementation's behaviour, ADR 0233) differs on 44,212 R0 reads and 7 R1 reads: the loop-marker rule is observable on the authentic routes and the choice is the GPGX one; it is a recorded assumption, not a verified hardware fact.

## Gate

`PCM_DIFFERENTIAL_GO`: correct advancement and transition behaviour against an independent small-state oracle (closed form), against the reference's chip code on synthetic sequences and on authentic operation streams, and identical under deadline partitions; the unsupported classes stay typed stops.
