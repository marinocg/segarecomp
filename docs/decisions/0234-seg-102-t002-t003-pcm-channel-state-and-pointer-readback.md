# ADR 0234: SEG-102-T002/T003 - minimal PCM channel execution state and the CPU-visible pointer readback (M6)

- Status: Accepted. Milestone SEG-102 (M6), tasks T002 (state, commit `feb1aa9`) and T003 (readback). Gates `PCM_CHANNEL_STATE_GO` and `PCM_READBACK_GO` (evidence: ADR 0235).
- Related: ADR 0233 (the specification and its sources), 0144, 0177.

## Decisions

1. **State.** `ScdPcm` gains `addr[8]` (27-bit running addresses), `running` (the complement of the last ON/OFF write), `origin` (the tick of the last chip reset) and `samples` (events applied), plus cost counters that survive a reset (`syncs`, `advanced`, `channel_steps`, `max_catchup`). Nothing else: no envelope, panning or output state is consumed, so no sound, mixer, buffer or callback exists.
2. **Clock.** The existing machine tick domain only. The period is `384 x scd_sub_cycle_ticks(m)` (the stopwatch's expression), so the BIOS-image profile's line-locked sub cycle and the synthetic profile's exact 12.5 MHz cycle both keep the reference's 1:384 CPU:PCM ratio. `scd_pcm_sync(m, t)` computes `due = ceil((t - origin) / period)` (the events strictly before `t`) and applies `due - samples` events. No wall clock, thread, floating point or second scheduler; the result is a pure function of the access instants and the register writes, hence independent of how the run is partitioned into deadlines (checked in T004).
3. **Cost.** A plain loop: events x running channels, each a wave-RAM byte read, a compare and an add. When the chip is disabled or no channel runs only the counter moves. Measured on the authentic routes in T006; no optimisation was needed.
4. **Writes.** Every PCM write synchronizes first (the chip's behaviour after the write depends on events before it). ST reloads an OFF channel; ON/OFF reloads every set (OFF) bit; the other register and wave RAM writes reload nothing. The power-on and RES0 = 0 resets clear the chip and re-anchor the grid at `m->now`.
5. **Reads.** Only the pointer registers (chip offsets `$10-$1F`) are served, to an odd-address byte read and to word reads (low lane = the byte, upper lane = 0). Everything else, including an even-address byte read, the other registers and the wave RAM read path, remains the typed stop `pcm_unsupported`, decided **before** any synchronization or state change. A served read is logged to the device log (event `$3A`).
6. **Diagnostics.** `--pcm-trace FILE` (local only) records every PCM write/read/reset with the machine tick, the value, the channel address and the sample counter; the report's `sub_devices.pcm` carries the running state and the cost counters. They are inert unless requested.
7. **Existing tests.** The sub-side table and the `subside` fixture expected `pcm_unsupported` for a pointer read; they now read a non-pointer register for the typed stop and gain rows for the served reads. The fixture-disc manifest is regenerated (the `subside` negative case changed; the new `pcm` fixture, ADR 0235, is added).
