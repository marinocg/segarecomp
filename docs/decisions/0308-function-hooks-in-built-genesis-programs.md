# ADR 0308: Function hooks in built Genesis programs (native ABI 2, headless and played)

- Status: accepted (SEG-138-T012). Completes the integration deferred by ADR [0298](0298-genesis-static-function-hooks.md) and ADR [0300](0300-scheduled-mods-in-built-programs-diff-run-test-and-gameplay-example.md) on top of the native provider seam of ADR [0305](0305-live-scheduled-mods-and-native-abi2-providers-in-built-programs.md). The hook semantics themselves (modes, cycle accounting, ordering, transactional failure) are ADR 0298's and are unchanged.

## Decision

1. **Where hooks run.** A native ABI 2 package that declares `[[hook]]` sites is linked by `segarecomp build --native-package` into the headless program (frame capture, `mod diff-run`, `mod test`) and into the played SDL3 program. Both use the one scheduler adapter (`platforms/genesis/viewer/mod_capture.cpp`); nothing is a second lifecycle.
2. **Manifest to plan.** The build resolves the declarations against the exact source image (`resolve_hooks_for_image`: verified symbols only, `E_HOOK_DIGEST` when the image digest is none of the declared revisions) and writes a build-private plan (`<output>/hooks/function_hooks.plan`): the resolved sites, and the exception/interrupt vector targets read from the effective image's vector table (vectors 2..63, non-zero). The emitter's CLI route takes it as `emit-general-startup-bridge-c --function-hooks <plan>`; it classifies every site against the compiled program (ADR 0298's `E_HOOK_*` table) and emits the hook wrapper only for a hooked build. A program without hooks is byte-for-byte what it was.
3. **Fail closed.** A classification failure surfaces as the stable class in `status.json` (`diagnostic`) and in the `@result` line, stops the build at `generate`, and leaves no executable. Declaration-level rejections of a (crafted) package keep their `E_HOOK_*` class instead of the generic invalid-package class.
4. **Bindings are cross-checked twice.** The build derives one binding per resolved site (site id, `hook_id` = the declaration's index in the id-sorted manifest) into the constant artifact, scans the generated site table and refuses a binding that names no generated site (`E_HOOK_BINDING`); the program repeats the check at attach (`MOD_REFUSED`). `hook-entry` is registered when a site is `before`, `before-after` or `replace`, `hook-exit` when `after` or `before-after`. A hook scoped to another revision has no site here and is not bound; a package whose hooks apply to no revision of the image is `E_HOOK_REVISION`. The generated program exports the const site table only through `genesis_generated_hook_sites`, which also lets the scheduler save and restore hook call frames in flight by site index (ADR 0299).
5. **Luau hook callbacks stay unsupported.** A Luau package that declares hooks is refused at build with `E_HOOK_CALLBACK_UNSUPPORTED`; no task owns them. `hook.function` is part of the native scheduled capability set only.
6. **Observability.** A hooked program's `MOD_LOADED` names the number of linked hooks and `MOD_SUMMARY` carries `hooks: {entry, exit, abandoned, unproven, overflowed, checkpoint_depth}`; `mod diff-run` reports the first five in the modded run's `mod.hooks` and `mod test` in each scenario's `observed.hooks` (the same parsed data; the field is absent for a program without hooks). The played program prints the same `MOD_SUMMARY` at exit. Programs without hooks print neither.
7. **The plan is an external input.** `--function-hooks` is parsed fail-closed before anything is generated: at most 16 KiB and 256 bytes per line, 1..64 sites, at most 62 distinct vectors, exact field counts, exactly eight lower-case hex digits, flags `0|1`, a decimal cost <= 65535, a token id, a known mode, no duplicate id or address; any violation is exit 2 with `function-hook plan rejected: ...`.
8. **Test-only seam.** `--test-hook-binding <id>` adds a binding that names no generated site so the cross-check can be exercised from the CLI; the launcher never sets it.

## Evidence

`tests/mod_hooks_build_test.py` (fabricated image, no commercial data): a no-op `before-after` hook leaves the headless program bit-identical to Vanilla (whole capture summary), `before`/`after` sites deliver only their phase, a committing `replace` reproduces the original's work RAM and frames, a declining one equals Vanilla, replay is identical, a save/restore taken with a call frame in flight (and a fresh program loading that state) reproduce the identical end state, the played SDL3 program reports hook counters proving the callbacks ran (and a marker-writing replacement is visible in its work RAM) and ends in the Vanilla frame and RAM for the no-op and declining packages, a fresh program loading an in-flight state converges on the uninterrupted run's RAM, frame, write digest and hook totals, `mod diff-run` reports the counters, a Luau package with hooks is refused, and every `E_HOOK_*` class is produced by the CLI build and leaves no executable. The cycle accounting, ordering and fault rules remain pinned by `genesis_mod_hook_scheduler_test` and `genesis_function_hook_*` (ADR 0298).

## Limitations

- Native ABI 2 only, Genesis M68K only, one mod. Several mods or exclusive ownership of a site are SEG-141-T003; Master System and Sega CD hooks are their own spikes.
- The viewer evidence is end-state equality with Vanilla (final frame and work RAM); hook counters are reported by both programs. In-flight save/restore is proven headless (`SEGARECOMP_MOD_CHECKPOINT`); the played program's quick-save and rewind use the same `MODSTATE` seam.
- No real-game hook claim: the evidence is a fabricated image.
