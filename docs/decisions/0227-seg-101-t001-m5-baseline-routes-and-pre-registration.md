# ADR 0227: SEG-101-T001 - M5 baseline, pre-registered routes and definitions (authentic unvisited-route execution)

- Status: Accepted. Milestone SEG-101 (M5), task T001. Fixed from the independent reference and the M4 baseline **before any gameplay-input run of a generated program**. It may only be made stricter later; a change of route, frame, threshold or definition after an outcome is observed invalidates the milestone's claim and is reported as such.
- Related: ADR 0221-0226 (M4), 0147/0148/0150 (Checkpoints F/G), 0175-0177 (Checkpoint H and the BIOS-image timing conventions), 0204-0207.
- Privacy: classes, counts and parameters only. No BIOS or disc byte, hash, address, LBA, file name, image id, level name, frame image or digest appears here. Everything with an identity (program hash, image ids, per-route reports, reference captures) stays under the ignored private directory of the operator's machine.

## Question

M4 showed that authentic modules can be compiled from the disc's files before any run and bound at run time without a supplied base. All nine modules it executed were already known to the execution-derived builder. M5 asks: does **one frozen, input-free build** execute an authentic module that **neither the build nor the baseline route ever loaded**, correctly, with no rebuild and no runtime compilation?

## Decisions

1. **Inputs.** The operator's legally held Sonic CD (USA) disc, the US Model 1 (V1.10) BIOS image, a formatted empty 8 KiB internal backup RAM (the image Checkpoints F-H used), port 1 a 3-button pad, port 2 a pad never pressed, empty cartridge slot. The independent reference is the private Genesis Plus GX driver (`scd_oracle`) under the Checkpoint F-H preconditions; for this task it gained one generic input schedule (`ORACLE_PADS="rel,len,BUTTON;..."`, entry-relative exactly like `ORACLE_START_REL`) and its three-pad Checkpoint H schedule reproduces the stored Checkpoint H reference frames byte for byte.
2. **Build B0 (the M4 baseline).** `segarecomp sega-cd build --file-first structural` from the merged M4 tree (origin/main `7a01bc6`), no `--input-script`, no module list, no extent list, no `--disc-image`, no per-title option; the existing static scan and execution-derived producers run as always and every extent they admit is recorded. Recorded privately and immutably (read-only file): program hash and size, program identity, hash of the generated-source tree (226 translation units), status, rounds (7), admitted extents (**3, all boot-system; 0 game-module extents**, 0 static-scan extents), the file-first inventory and policy identity, build cost (wall 243 s, CPU 601 s, peak child memory ~0.66 GiB with the object cache of earlier builds reused), the build pass's final typed stop, and the inventory limitations.
   Aggregate B0 facts: 131 ISO9660 files enumerated; **120 compiled as images** (22.0 MB; 1,536,888 offsets; 69,057 shared bodies); 4 over the 512 KiB bound (98.9 MB), 4 duplicates, 1 empty, 2 without structure; inventory `complete:false` (typed). B0's run on route R0 reproduces M4 (74,463,733 retired instructions; `pcm_unsupported` at the same tick; 9 images bound, 4 replacements; no refusals).
3. **Frozen program B1.** T002 adds an observer-only per-image account to the runtime (ADR 0228). That changes the runtime objects but **not one byte of the generated source tree or the program identity**; B1 is built once from the same inputs after T002, its source-tree digest and identity must equal B0's (reported), and B1 is the program every route of T003 runs. Between B1's build and the last route nothing is rebuilt, recompiled, relinked or re-emitted; B1's hash, source/object inventory and program directory are verified before and after each route, and a route is run with an empty `PATH` (no compiler or linker can be started) from a directory the program cannot write to.
4. **Observed-by-the-build set.** The build admitted no game-module extent, so the build's *module* knowledge is the execution of its own passes, which for an input-free build is the R0 route up to the same frontier. A source image is **build-observed** if at least one instruction retired through it during R0 on the frozen program (R0's final state equals the build's final pass; the earlier passes stop earlier on the same input-free route) **or** if its disc span overlaps an extent the build admitted. Identity is the compiled image (the immutable disc file), never a guest address: the same file at another base, a replaced file at the same base and a repeat load are the same / a different identity accordingly.
5. **Previously unvisited authentic module** = a compiled image that (a) was a file-first candidate, (b) is not build-observed, (c) was bound by the runtime's verified binder on some route, (d) retired at least one instruction through its precompiled bodies, with every executed instruction byte-verified against the image (the existing per-instruction guard). A delivered sector, a data file, a candidate, a bound-but-unexecuted image, an ambiguous or refused identification are **never** counted. A previously unexecuted instruction start inside a build-observed module is reported separately and never counts toward the milestone's central claim.
6. **Routes (frames are reference frames relative to the application entry, the onset convention of ADR 0147/0177; presses use the schedule form of ADR 0176 decision 3; `--base-onsets 1201`).**
   - **R0**: no input, run to the existing typed frontier (`pcm_unsupported`).
   - **R1** (the Checkpoint H schedule, unchanged): START pressed at entry+480 held 6; START at +600 held 6; RIGHT at +1260 held 240; compared to entry+1500. Reference frames: 510, 540, 600, 1150, 1250, 1300, 1400, 1500 (256x224 for the title frames, 320x224 for the level: 38/38/38/34/34/35/35/40 distinct canonical colours; 53,824-70,239 non-black pixels). It selects the first level - the title-menu choice "NEW GAME".
   - **R2** (independent alternative, chosen from the reference alone before any generated run): START at +480 held 6 (title menu), RIGHT at +540 held 4 (moves the menu choice from "NEW GAME" to "RAM DATA"; the menu has exactly these two choices with an empty backup RAM, as the reference's frames show), START at +600 held 6; compared to entry+1500. It selects a different gameplay-independent content class (the backup-RAM management screen, entered through a fade at about +620-640 and a load) rather than another direction in the same level. Reference frames: 510, 540, 600 (menu), 640 (black), 900, 1200, 1500 (the management screen; 19 colours, 71,646 non-black pixels, identical at 900/1200/1500). The reference is repeated: two runs identical at every frame. The reference's executed instruction starts to entry+1518 differ between the routes: main 6,946 (R1) against 4,246 (R2) with 3,112 shared, sub 5,241 against 5,139 with 5,081 shared (R1-only 3,834 main / 160 sub; R2-only 1,134 / 58) - the routes do not exercise the same code, in the reference.
   - No other route is added. If R1 and R2 exercise the same modules that is reported as such.
7. **What is compared, per route, within the route only.** The canonical frame digest and dimensions at each frame above; VDP registers, CRAM, VSRAM and VRAM; both CPUs' registers (program-counter classes) at the compared frames; Work RAM, PRG RAM and Word RAM; the controller observations; the typed stop and the stop instant; executed instruction starts and retired totals (against the Compatibility control below). Asynchronous differences are classified exactly as in ADR 0147/0148/0176/0177 (polling-loop pc and the data it alone writes, stack residue below the stack pointer, BIOS status and sub-stack bytes, sound-driver state no frame reads); nothing else is relaxed.
8. **Control.** A route-specialized Compatibility build: the supported build with `--input-script` of the same route (execution-derived extents for that route; its distinct program identity is recorded). Its extents are never transferred to B1. State equality of B1 and the control is evaluated route by route.
9. **Outcome rule (M5 acceptance, restated).** `AUTHENTIC_UNVISITED_MODULE_GO` iff a module satisfying decision 5 executes on R1 or R2 from B1 and B1 equals the reference on the accepted interval of that route; `AUTHENTIC_UNVISITED_MODULE_NOT_DEMONSTRATED` iff every executed image on every route is build-observed; new instruction starts in build-observed images only is a separate partial result. A stop on a route is classified with ADR-registered frontier classes (`body_not_compiled`, `no_source`, `no_delivery`, `ambiguous_image`, `ledger_overflow`, `unsupported_dynamic_body`, `non_iso_source`, `oversize_file`, `transformed_code`, `static_dispatch_conflict`, or an independently verified device stop); no route, frame, input or threshold is changed after an outcome.
10. **Reproduction commands (private paths elided).** Build: `segarecomp sega-cd build --cue <disc.cue> --bios <bios.bin> --output <dir> --runtime-dir <root> --cc cc --jobs 8 --cache-dir <objects> --backup-ram <bram.bin> --file-first structural`. Route scripts: `tools/sega_cd_input_script.py onset --base-onsets 1201 --press <N> --hold <H> --button <B>` for each press of decision 6 (R1's output equals the stored Checkpoint H script). Reference: `scd_oracle` with `ORACLE_PADS` equal to R1 `480,6,START;600,6,START;1260,240,RIGHT` and R2 `480,6,START;540,4,RIGHT;600,6,START`, `ORACLE_NO_CART=1`, `ORACLE_BRAM_FORMAT=1`, canonical frames as listed.

## Gate

`AUTHENTIC_ROUTES_PRE_REGISTERED`: met. A meaningful alternative route (R2) was established independently of any M5 outcome. No generated program has yet run R1 or R2.

## Limitations stated in advance

The frontier of R0 (`pcm_unsupported`, about 2,170 frames after entry) lies beyond both R1's and R2's compared interval; whether R1 and R2 reach their ends without a device stop is part of T003, not assumed. Inventory limitations of M4 (files over 512 KiB, non-ISO sources, transformed code, structural admission recall below 100 %) stand and are carried into T005.
