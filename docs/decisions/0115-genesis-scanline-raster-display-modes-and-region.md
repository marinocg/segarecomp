# ADR 0115: Scanline-aware raster state, generic display modes, H-interrupt and console region (SEG-055)

- Status: accepted (SEG-055-T001, one combined product PR).
- Contract: `docs/architecture/genesis-raster-and-display-modes.md` (behavior, capability matrix, references).
- Context: six reported multi-game compatibility problems -- mid-screen palette switches (Sonic 1 water), interlace-mode-2 two-player split screen (Sonic 2), road scrolling glitches (OutRun), H32 (Flicky, Sonic 2 special stage), a "playable only on NTSC systems" lockout (Sonic 3 Japan), and a missing HUD (Streets of Rage, Window plane) -- all trace to missing *generic* hardware behavior, not game logic.

## Decisions

1. **Per-scanline mutable state, not per-line VRAM and not an event log.** The renderer previously consumed one final snapshot. The smallest deterministic mechanism that preserves visible mid-frame changes is the 256-byte per-field-line state (register file + CRAM + VSRAM) captured as each active line begins, plus the single VRAM image at the frame boundary. Alternatives rejected: a VRAM snapshot per line (64 KiB x 224, wasteful and unnecessary because CRAM/VSRAM/registers are what raster handlers change); a write-event log (needs ordering/replay semantics and a second consumer of the same state; per-line state is a straightforward function of the event stream at line granularity and keeps the renderer a pure function of its inputs). VRAM bytes written *during* the active display are the one VRAM exception: they are journaled (bounded, line-tagged, replayed over a line-0 snapshot) because two-player split screens swap the sprite attribute table in the middle of the picture; an overflowing journal falls back to the frame-end image and is counted.
2. **One renderer.** `vdp_render.c` stays the only composition owner; the previous per-pixel functions are generalized, not duplicated. Existing public helpers keep their signatures and behavior for H40/non-interlaced; shapes that became supported (H32, interlace mode 2, scroll mode `10`) have their former fail-closed unit tests rewritten to assert the new behavior, while every reserved or unsupported shape keeps a fail-closed test. A render validates everything up front, so a failure writes nothing.
3. **H-interrupt is scheduler state, not a device.** The counter/latch live in the runtime-private `GenesisRasterScheduler` next to the other scheduler state (never in `GenesisDeviceState`, so the checkpoint-evidence schema and its independent oracle are untouched), advance on the existing deterministic master clock, and reach the CPU through the M68K-owned interrupt core (level 4, vector 28, autovector). The handler entry is resolved by static discovery like the other build-time vectors (bounded, additive root with a retry that drops it if it would cause a rejection -- see the contract); no runtime decoding or target fetch exists. An enabled interrupt without a resolved handler is counted and dropped by default (the pre-existing behavior, now observable) or stops fail-closed in strict mode.
4. **Frame artifact grows geometry and per-row palettes, with a legacy-compatible digest.** Zero-initialized == the old artifact; legacy-shaped frames hash exactly as before so every oracle/golden stays valid; any other shape hashes its geometry and palettes too. The checkpoint bundle digest hashes `width * height` pixel bytes (identical for legacy frames). The independent checkpoint oracle was updated to the same rule and its digests are compared against the runtime's in the existing suites.
5. **Pacing authority is the virtual frame counter.** `GenesisRuntime::virtual_frame_count` advances at every VBlank onset regardless of rendering; the viewer waits per boundary and presents when a new frame exists. Decoupling removes the failure mode where a rejected display mode removed throttling.
6. **Region is console configuration resolved at run time.** The version register reads the configured profile (default USA NTSC = the previous constant). The static seam defers the byte read to the runtime owner so one generated program serves every profile; selection is the host API or `SEGARECOMP_GENESIS_REGION` (the existing env-var launcher channel), fixed before the first step; the bridge exposes `--region` and records it in run summaries. PAL has a version value but is refused honestly -- 50 Hz timing is not implemented. No fingerprints, no PC checks, no ROM patching, no bypass of the cartridge's own check.
7. **Fail closed.** Reserved RS0/RS1, interlace mode 1 and the reserved LSM value, V30, Mode 4, reserved plane sizes, scroll mode `01`, a geometry change inside a frame and PAL all stop or reject explicitly. An enabled H-interrupt that cannot be delivered is counted and reported (default) or stops (strict); this is a deliberate compatibility policy rather than a silent drop because the H-interrupt has never been delivered by earlier builds and many titles (RAM-resident or run-time-constructed handlers) would otherwise stop where they previously ran.

## Consequences

* The generated code gains one extra analysis root (vector 28) in every build; builds whose slot cannot be admitted are unchanged. Generated programs that read `$A10001` now route the byte read through the runtime device owner (previously folded), so builds that exercise it differ textually while remaining behavior-identical in the default USA profile.
* Titles that enable the H-interrupt now observe it when its handler could be compiled; titles whose H-interrupt vector is RAM-resident have the request counted as undelivered by default (previously it was silently never raised; strict mode stops), which is the honest signal for a follow-up that resolves RAM jump-table vectors the way IRQ6 does.
* The frame artifact is ~176 KiB (was ~72 KiB); it remains plain data copied only at frame boundaries.
* Limitations (section 1 of the architecture contract): no shadow/highlight, no sprite X = 0 mask, no display-disable, no sub-line timing of any write or of the H-interrupt, V30 and PAL unsupported; an H-interrupt vector reached through a RAM stub is resolved only when the build-time preparation materializes a byte-guarded thunk or copy alias for it (otherwise an enabled H-interrupt stops fail-closed).

## Verification

Synthetic suites listed in the architecture contract (section 8) plus the existing renderer/export/evidence/viewer/IRQ6 suites. Real-game observations are local, ignored-path diagnostics only and are recorded as classifications in the task evidence; no ROM bytes, captures, traces or generated commercial C are committed.
