# ADR 0102: SEG-049-T003 native build-time inference of the frozen gen2 M3 CNN with B35 rank-budget selection

- Status: accepted (checkpoint C1 of the combined SEG-049-T003..T007 delivery). **Production default unchanged.** Compatibility (broad AOT) is the default; `optimized`
  remains the SEG-047 v1 route; gen2 is a new, explicit, opt-in producer added beside v1 (policy plumbing is T004/T005).
- Predecessors: ADR 0100 (gen2 representation, M3 selected), ADR 0101 (rank-budget calibration, B35, research freeze), ADR 0096 (SEG-047 native v1), ADR 0099.
- Evidence statement (inherited, unchanged): the five source-backed titles are **not blind**. B35 is an empirical generalization hypothesis chosen from a five-point grid on
  them, not a completeness proof, and the structural validator does not prove that unselected code is never executed. This ADR ports the frozen candidate; it does not
  change the model, the budget, the representation or the selection semantics, and it makes no default or universal-support claim.

## 2. Architecture

`ROM -> CPU-owned decode tokens -> frozen native M3 -> B35 rank selection -> (existing structural prune + admission validator, unchanged) -> generated C`.

- `platforms/genesis/machine/src/ml_region_gen2_producer.cpp` (+ header) is a fixed evaluator for exactly the one frozen architecture (36-channel input; Conv(5, d1, 48) -
  Conv(5, d2, 48) - MaxPool(2) - Conv(5, d2, 64) - Conv(5, d4, 64), BatchNorm folded, ReLU; head = mean/max over the 32 cell positions and over all 226 final positions ->
  Linear(256, 64) - ReLU - Linear(64, 1)). No tensor/graph abstraction, no model loader, no operator registry, no future-model extensibility.
- Weights are an embedded, checked-in generated table (`ml_region_gen2_model_data.inc`, 77,441 trainable parameters, ~1.1 MB of source; generated by
  `tools/segarecomp_ml_region_gen2_native_data.py`, `--check` is the drift test) from `tools/segarecomp_ml_region_gen2.model.json` (SHA-256
  `11258708285e4427a3e38e02732e8f93b4c5d497883101f0629223d2366a98e1`). No file is read at run time; there is no Python, PyTorch, ONNX, TensorFlow, JIT, download or runtime
  guest-opcode decoding. The binary never evaluates anything at guest run time.
- Tokens come from the single CPU-owned definition `genesis_decode_tokens` (the report `m68k-decode-token-report` is now a framing wrapper of it): there is no second
  token implementation. The token-schema pin is a label: decoder drift is detected by the golden CPU-token digests (synthetic corpus) and the unchanged token tests, not by the pin. Token values are range-checked against the frozen field cardinalities before any table lookup (fail closed `token_range`).
- Whole-image evaluation uses a shared convolutional trunk over a reflected, padded image in chunks of 64 cells (peak scratch memory is a few MiB, independent of image
  size). Because all convolutions are valid, a cell's logit depends on exactly its 512-word context; this is tested bit-for-bit against an explicit per-context construction,
  for several chunk sizes, for ROM-edge and partial-last cells and for images shorter than the pad.
- Selection (`genesis_ml2_rank_select`) takes only `(span<const float> logits, unsigned percent)`: binary32 logit descending, **cell ordinal ascending as the only tie-break**
  (the ordinal never reaches the model), `N = ceil(cells * percent / 100)` in integers, strictly rejecting non-finite logits. The production percent is the embedded B35.
  `R = rank-selected cells U certain-code seed cells`. Ranking by the logit instead of the research sigmoid is order-equivalent except where the research double sigmoid
  saturates; no saturated group straddles a budget cut on the five titles (exact digests below).

## 3. Numeric contract and tolerance policy

1. The network is IEEE-754 binary32 with a fixed accumulation order: per output channel `bias`, then taps 0..4, then input channels in order, one binary32 multiply and one
   add each (a zero input is skipped, which adds exactly nothing); head sums left to right. BatchNorm is folded at first use in binary64 (`+ - * / sqrt`, all correctly
   rounded) and rounded to binary32. The translation unit is built `-O2 -ffp-contract=off -fno-fast-math` (and `#pragma clang fp contract(off)`).
2. Under that contract the logits are **bit-identical** on every IEEE-754 host. Measured: identical logits digests for the synthetic image and for Flicky and Sonic & Knuckles
   under GCC -O2, GCC -O3 -march=native (FMA hardware), clang -O3 -march=native and clang -O0; the same translation unit compiled with `-ffp-contract=fast` produces different
   digests on all three, which is why the flag is part of the contract and why a bitwise golden is asserted by every CI platform (macOS arm64 contracts by default).
3. The logits are **not** bit-identical to the research evaluators (different summation order), so the gate against them is two-fold and neither half replaces the other:
   (a) a documented absolute logit tolerance `1e-4` (observed against PyTorch 2.14.1 float32: max 1.53e-5 over all 39,936 cells of the five corpus titles, mean 2.1-2.6e-6, max
   9.5e-6 on three synthetic images; against the stdlib double reference on the three ADR 0101 probes: <= 3.7e-6), and (b) **exact selected-cell-set equality**, which is the
   correctness gate. A numerical difference is acceptable only if it cannot change the selected set; the weakest logit gap across the budget cut on the five titles is 6.6e-4
   (Sonic & Knuckles; in-sample, margin not a guarantee for other images), > 6x the tolerance and > 40x the largest observed difference. A tie group is exact in both implementations (identical contexts give bitwise equal logits).
4. Production selection is *defined by* the bitwise-deterministic native contract, not by the research evaluator; if a toolchain ever violated the contract, the committed
   golden digests (`tests/genesis_ml_gen2_test.cpp`, `tools/segarecomp_ml_region_gen2.native_parity.json`) fail on that platform rather than silently changing a selection.

## 4. Results (aggregates and digests only; no address, score or ROM byte is stored)

Exact native/research selected-cell parity on all five source-backed titles (native frozen final model == the committed in-sample digests of
`segarecomp_ml_region_gen2.parity.json`):

| title | cells | selected (B35) | boundary tie group | weakest-selected minus strongest-unselected logit | selected-set digest equal | ML-only region == research region | K stage (prune + production validator) == research K | repeated runs identical |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Sonic 1 | 4,096 | 1,434 | 1 | 3.39e-3 | yes | yes | accepted, K 86,654 / U 246,293, identical plan | yes |
| Flicky | 1,024 | 359 | **559 identical-score cells straddle the cut** | 0 | yes | yes | accepted, K 22,274 / U 64,352, identical plan | yes |
| Shining Force | 12,288 | 4,301 | 1 | 3.04e-3 | yes | yes | accepted, K 253,872 / U 735,560, identical plan | yes |
| Phantasy Star II | 6,144 | 2,151 | 1 | 2.23e-3 | yes | yes | accepted, K 123,574 / U 367,930, identical plan | yes |
| Sonic & Knuckles | 16,384 | 5,735 | 1 | 6.60e-4 | yes | yes | accepted, K 351,182 / U 989,195, identical plan | yes |

"Research" here is the PyTorch final all-five-title fit (`run1.scores.npz`, private) ranked by the research `rank_select`, region-serialized by `regions_text`, and pruned/validated
by the same unchanged CLI stage; the native region file is byte-identical, so the admitted set is identical by construction. (The seed cells, direct-control instruction cells, were
all already inside the top-ranked cells on every title, so `R == ML-only`.) These are *in-sample* K values of the final model; the held-out figures of ADR 0101 are unchanged.
The Flicky row is the ADR 0101 low-score tie group: both implementations score the identical-context cells identically and the ordinal tie-break resolves them identically.

Cost (single thread, GCC `-O2` evaluator in a Debug build; the token decode runs at `-O0` here and is faster in release builds): inference 0.29 s (Flicky, 128 KiB) / 1.41 s
(Sonic 1, 512 KiB) / 2.09 s (PS2) / 4.19 s (SF1) / 5.34 s (S&K, 2 MiB), i.e. ~2.5 s per MiB; tokens 0.08-1.6 s; **peak RSS 9-19 MiB** for the evaluator alone (the 0.2-0.85 GiB
of a full CLI run is the broad analysis). ADR 0100's estimate was 20 / 40 / 80 G MAC for 1 / 2 / 4 MiB and 307,972 bytes of folded weights; the measured throughput is ~7.5 G MAC/s
without SIMD intrinsics or threads, ~3.8x slower than the PyTorch CPU time quoted there (1.4 s for 2 MiB, an optimized MKL-DNN kernel) and far below the compile savings of
ADR 0101 section 10. Threads and intrinsics were not added (no speculative optimization); they remain available without changing results because every output position is independent.

## 5. Tests

- `genesis_ml_gen2_test` (hermetic C++): identity, integer budget arithmetic (the five research budgets 359/1434/4301/2151/5735), reflection, chunk-size invariance (bitwise),
  per-context equality incl. both ROM edges, partial last cell and images shorter than the pad, position independence, golden CPU-token / logits / selection digests, rank
  selection (identical scores, straddling tie group, adjacent binary32 near-ties, signed zero, NaN/inf rejection, monotone invariance, exact N), proposal union/ranges, fail-closed reasons.
- `segarecomp_ml_region_gen2_native_test` (hermetic Python): generator drift, source pins == frozen record, frozen/v1 artifacts unchanged, no forbidden runtime dependency in the
  producer, selection signature has no label/title input, probe tolerance and **bitwise** probe goldens, synthetic-image tokens/logits/selection goldens with an independent stdlib
  re-selection, deterministic CLI region proposal.
- `tools/segarecomp_ml_region_gen2_native_parity.py local|reference`: the local five-ROM gate above and the synthetic PyTorch cross-check (both self-skip, exit 77, when the inputs are absent).

## 6. Limits

- Known five-title corpus; no new blind evidence; no claim for other ROMs. Inference cost is real build-time work (not free) and is not yet multi-threaded.
- The bitwise goldens assume an IEEE-754 binary32 host with the build flags above; a platform that cannot honour them must fail the golden, not be waved through.
- The CLI seams added here (`--ml-gen2-region-proposal-output`, `--ml-gen2-logits-output`, `ml-gen2-cell-logits`, `ml-gen2-probe-report --synthetic`) are report-only and cannot alter generation.
