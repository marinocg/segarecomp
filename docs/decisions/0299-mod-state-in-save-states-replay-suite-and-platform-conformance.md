# ADR 0299: mod-owned state in save states and rewind (`MODSTATE`), the replay/determinism regression suite and the platform conformance suite

- Status: accepted (combined delivery F10: SEG-138-T006, SEG-138-T007, SEG-146-T004). Implements section 6.2 and the tests of section 7 of [mod-execution-phases.md](../architecture/mod-execution-phases.md) ([ADR 0282](0282-mod-execution-phases.md)) for the Genesis scheduler of [ADR 0297](0297-genesis-mod-phase-scheduler-and-work-ram-services.md) / [ADR 0298](0298-genesis-static-function-hooks.md), on top of the SEG-131 container of [ADR 0278](0278-genesis-save-states-persistence-and-rewind.md).
- Not in scope: linking a mod into a CLI-built program (SEG-138-T009), several mods in one state (SEG-141), Master System / Sega CD containers (SEG-147 / SEG-148), real-game scenarios (SEG-138-T008).

## Decision 1 (SEG-138-T006): a `MODSTATE` section, joined to the container through a seam, never a link

`genesis_snapshot.c` is compiled into generated programs and viewers and must not link a scheduler. `GenesisSnapshotMachine` therefore gained one optional pointer, `mod` (`GenesisSnapshotModState`: identity, schema, a compatibility digest and five entry points). `genesis_mod_snapshot_state(scheduler, &table)` fills it. With `mod == NULL` nothing changes: no flag, no section, and the container is byte for byte what it was (the existing snapshot/rewind/persistence suites are untouched).

With a mod the machine profile gains `GENESIS_SNAPSHOT_FLAG_MOD (0x0010)` and the container section 11, `MODSTATE`, is required. Its fixed header is `{ version u32 = 1, identity[32], state_schema u32, compat[32], body_length u32 }` (76 bytes), followed by the body (at most 64 KiB + 2 KiB; the section maximum is ~66 KiB). The execution fingerprint folds in identity, schema and `compat`, so a state is restored only into a build whose mod identity, declared `state_schema` and compatibility digest (ABI major, granted capability sets, registered phases, declared ranges, hook bindings, provider implementation version) are all equal. The decision order in `precheck` is: structure and integrity, source/variant identity, **mod presence** (a state with a mod into a build without, or the reverse: `E_STATE_MOD_MISMATCH`), **mod identity / schema / compat** (`E_STATE_MOD_MISMATCH`), then the generic fingerprint. Nothing is staged, and no mod entry point is called, before these pass.

The body (little-endian, scheduler-owned, `mod_scheduler.c`) holds exactly the state that decides the mod's future: the disabled/started/fault flags and the stable fault diagnostic (phase, frame, cause, text); the per-frame pad latch and the interception the guest reads (`mod_pad_*`); callback and hook counters; the streamed SHA-256 context and total of every committed write (the replay witness continues exactly across a restore); function-hook call frames in flight (site by index into the program's site table, return PC, entry SP) with their counters; and, with `state.mod`, the provider's own blob (`save_state`, at most 64 KiB, schema-versioned by the section header). Not saved: the retained diagnostic write log (it restarts empty; its count reappears as "not retained" and the digest is exact), staged data (none exists at the barrier) and the render copy. A disabled mod has no blob: its flag is its whole state.

Restore keeps the SEG-131 two-phase guarantee. The mod body is *staged* (every value validated: flag consistency, `disabled == faulted`, a pad latch only for an enabled `input` mod, hash-stream length equal to 28 bytes per committed write, hook frames only for `after` sites in range, exact blob length, no trailing bytes) before anything is replaced. The only fallible step is the mod's own `load_state`, so it runs **first** in the commit, before any guest memory or clock is touched: if the mod refuses, the restore is `E_STATE_MOD_REJECTED`, the guest state is byte-identical, and the mod's previous blob is put back; a mod that cannot even take its previous state back is disabled (`E_MOD_FAULT cause=state`) - the guest stays untouched in every case.

`E_STATE_UNAVAILABLE`: a guest-affecting mod (`memory.write`, `input.intercept`, `hook.function`, `audio.command.send`) that does not declare `state.mod`, or whose `save_state` fails or exceeds 64 KiB, makes capture fail (`GENESIS_SNAPSHOT_MOD_UNAVAILABLE`); the rewind engine already turns a failed capture into "Rewind stopped: <reason>", never a silently wrong state. A read-only mod needs no `state.mod`.

`state.mod` is now served by the scheduler (it was refused as `E_CAPABILITY_UNSUPPORTED`). Attach additionally requires `save_state`/`load_state` and a declared `state_schema` when it is granted (`E_PROVIDER_ENTRY`, `E_STATE_SCHEMA`). The Luau provider table now fills `save_state`/`load_state` with the VM's one canonical value (`save()` / `load(v)`, depth <= 8, <= 64 KiB; ADR 0295). A Luau fault is sticky: a faulted VM cannot take a state back, so restoring an enabled state into it is `E_STATE_MOD_REJECTED` (restore into a fresh session instead; a native mod resumes).

Rewind needs no code of its own: the viewer state service captures and restores through the same functions, so history entries carry the mod section and a rewind restores the mod state with the guest (the resumed future is a new history branch; `reset` does not run).

## Decision 2 (SEG-138-T007): the replay and failure regression suite

`genesis_mod_replay_tests` runs a native and a Luau twin of one mod (input interception, RAM writes, counter state) on the synthetic program under a recorded pad sequence (a pure function of the frame number): two replays have identical per-frame state hashes and write witness; a different recording differs; save/run/restore/replay reproduces the hash sequence in the same and in a fresh session; sandbox failures during replay (native range violation, Luau budget exhaustion, Luau script error, with watchdogs off so they are deterministic) produce the stable `E_MOD_FAULT cause=<c> mod=<id> phase=frame-begin frame=<n>`, discard the faulting callback's staged write, end pad interception, leave the mod inert, and replay identically including from a pre-fault state restored into a fresh session; a post-fault state restores as disabled. Incompatible states (other identity, schema, capability set, region, source image, another mod kind) are rejected with the machine untouched and the mod's load never called; truncations, corruption (unsealed) and every sealed single-bit edit of every `MODSTATE` byte are either rejected with the machine byte-identical or accepted as a self-consistent state that the next good restore fully replaces. Bounded: at most 48 frames per run, one container edit per restore, no ROM, wall clock or host RNG; part of the `fast` set.

## Decision 3 (SEG-146-T004): one platform-parameterized conformance suite

`mod_platform_conformance_tests` is table-driven over `mod::adapters()`. Each registered platform declares, per scenario (`capability_negotiation`, `sdk_negotiation`, `phase_ordering`, `typed_guest_access`, `mod_state_round_trip`, `sandbox_failure`, `incompatible_target`, `audio_command_mapping`), either `pass` or the exact fail-closed diagnostic, plus its capability support-level table. A scenario first asks the registry (`check_capabilities`) whether the platform grants what it needs; if not, the outcome is the registry's `E_CAPABILITY_UNSUPPORTED`; otherwise the platform's executor runs it, and a platform that declares support but has no executor yields `E_RUNTIME_UNAVAILABLE`. The suite therefore fails when a declaration is flipped without the runtime (and when a runtime lands without its declaration). Genesis passes every supported row; Master System and Sega CD assert `E_CAPABILITY_UNSUPPORTED` for everything beyond lifecycle and `host.log`; the portable Luau sandbox rows (lifecycle, error and budget classes) run on every platform because the VM is platform independent. The audio-command row asserts the Genesis scheduler's `E_CAPABILITY_UNSUPPORTED:runtime` (it flips to `pass` with SEG-145-T008) and the declared refusal on Master System / Sega CD (flips with SEG-145-T013); there is no hard dependency on the audio tasks. Negative tests prove that a deliberately wrong declaration, a missing row for a registered platform and a row for an unregistered one each fail the suite. A new platform adds a row (and an executor), not a suite.

## Rejected alternatives

Serializing the whole `GenesisModScheduler` struct (pointers, staged buffers and a 64 KiB render copy are not state); linking the scheduler into the snapshot module (programs without mods would carry it); re-running the mod's `reset` after a restore (the contract says it does not run); committing the mod load after the guest copies (a refusal would leave a half-restored machine); one conformance executable per platform (the point is that a new platform adds a row).

## Limitations

- One mod per scheduler and per state; several mods are SEG-141. The state exists only for the Genesis container; Master System / Sega CD containers are SEG-147 / SEG-148.
- A mod that refuses its restore and also cannot take its previous state back is disabled, and `mod_pad_active` is cleared with it: that is the only host-side effect of a refused restore, by the fault contract.
- Hook frames in flight can be saved only when the host supplies the program's site table (`GenesisModConfig::sites`); otherwise a capture with a frame in flight is `NOT_CAPTURABLE` rather than lossy.
- Evidence is a synthetic hand-written program with native and Luau twins, not a generated-native program of a built fixture ROM; the end-to-end gameplay example is SEG-138-T009 / T008.
