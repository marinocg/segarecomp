# ADR 0294: Luau vendoring, the restricted per-mod VM and the trusted compile step

- Status: accepted (SEG-137-T001..T003, combined delivery F06). Implements [ADR 0284](0284-luau-trust-policy.md) / [luau-trust-policy.md](../architecture/luau-trust-policy.md) sections 2-4.
- Related: ADR 0281 (schema 3), 0288 (host implementation), 0289 (variant identity).

## Decision

1. **Pinned vendoring.** Luau release 0.746 (commit and archive digest in `third_party/luau/PIN.txt`) is vendored unmodified: `Common`, `Ast`, `Bytecode`, `Compiler` and `VM` only. `SHA256SUMS` lists every vendored file and `tests/luau_build_test.py` recomputes it. The build needs no network. Native code generation (`CodeGen`), `Analysis`, `Config`, `Require`, `Inliner`, the CLI and Luau's own tests are **not vendored at all**, so the JIT is not merely disabled: its code does not exist in the repository. Of the vendored VM sources, `linit.cpp`, `loslib.cpp`, `ldblib.cpp` and `lcorolib.cpp` are not compiled: `os`, `debug` and `coroutine` are absent from the binary, and the host opens each allowed library by name. `luaL_sandbox`/`luaL_sandboxthread` live in `linit.cpp`, so `luau_vm.cpp` carries their small equivalents for the libraries it opens.
2. **A new library `libs/luau_host`** (`segarecomp::luau_host`: compile step, provenance check, VM) between `libs/media` (which stays free of Luau) and the CLI. Third-party code is built with `-w`; the host library and its tests use the project's warning flags.
3. **Trusted compile.** `compile_mod` compiles every `luau-source` payload with fixed options (optimization 1, debug 0, no type info, no coverage; `getmetatable`, `tostring`, `math.random` and `math.randomseed` excluded from fastcall builtins because the host replaces them and a fastcall would bypass the replacement). Output is deterministic. Errors are `E_LUAU_SYNTAX` with the stable text `<package path>:<line>: <message>`; size/time overruns are `E_LUAU_COMPILE_LIMIT` (512 KiB bytecode per mod, 5 s). The *bytecode digest* = SHA-256 over the compiler pin and options, the package identity and each script's `path source_sha256 bytecode_sha256`. It is recorded as the `luau_bytecode` component of the variant identity (so a different compiler, option or script is a different variant) and in the `mod build` output.
4. **Provenance.** `CompiledMod` can only be produced by `compile_mod` or `verify_compiled`, and `Vm::load` accepts nothing else, so no code path hands package bytes to `luau_load`. `verify_compiled` accepts stored compiled output only if it is well formed, names the same package identity, covers exactly the package's `luau-source` payloads with their verified source digests, every bytecode digest recomputes, and the total digest equals the one **recorded at build time outside the artifact**. Anything else is `E_LUAU_COMPILED_MISMATCH`. `mod variant` stores the artifact (`luau.bin`) next to `variant.txt` and treats a modified, truncated, replaced or missing artifact as a cache miss that is rebuilt from source, never loaded. A package carrying bytecode never reaches this point: the reader already rejects non-text `luau-source` payloads (`E_LUAU_BYTECODE`) and unknown payload kinds.
5. **Restricted VM** (`luau::Vm`). One `lua_State` per mod with its own allocator. Globals are rebuilt from the policy whitelist (everything else the base library registers is removed), library tables, the string metatable and the globals are read-only, each mod runs in a thread with its own globals table, `getmetatable` answers for tables only, `math.random` is the stateless splitmix64 stream seeded per callback from `SHA-256(identity || frame u64 LE || callback index u32 LE)` (golden sequence, independently reimplemented in `tests/luau_host_golden_test.py`) and `math.randomseed` faults; `math.random` arguments must be integers in the 32-bit range; `tostring` renders tables, functions, userdata and buffers by type name only (no host addresses). `pairs` order over tables keyed by tables or functions remains host-dependent (policy section 3, SEG-137-T005 lint). The watchdog is on by default (policy) and can fault a mod on a very slow host; such a fault is flagged non-deterministic.
6. **Limits** are enforced by the host, not the script: the allocator refuses growth past the quota (memory fault); the interrupt callback counts one budget unit per VM safepoint (function call, loop back-edge, pattern-matcher step; garbage-collector steps are not units) against the per-callback and per-frame budgets and checks `lua_stackdepth` against the call-depth limit; a wall-time watchdog (4 ms per callback, 8 ms per frame, checked every 256 units) is a hang backstop whose fault marks the VM `nondeterministic()`. Every fault is **sticky**: after the first fault every later safepoint raises again, the C++ side holds the fault flag, and the mod is disabled once the callback returns, so `pcall` can neither clear nor outlive it. A fault disables only that VM.
7. **Teardown** closes the state and compares the allocator's byte count with zero (`Vm::close()` returns the leaked bytes). A CI job runs the host tests under ASan + UBSan (`-DSEGARECOMP_SANITIZE=ON`).

## Consequences

- `mod build` and `mod variant` now run the Luau compiler; `mod check` and `mod pack` still run nothing. A Luau syntax error therefore fails `build`, not `pack`.
- Existing variant keys of packages with Luau change once (new `luau_bytecode` component).
- No host API (`sega.*`), no frame/event callbacks and no analysis exist yet: SEG-137-T004.. build on `Vm::call`.
- The compile step's 256 MiB memory bound of the policy is **not metered** (the vendored compiler allocates through the system allocator); it is bounded structurally by the 128 KiB per-file and 1 MiB per-mod source limits. The 5 s limit is checked after the compile. Both are recorded as limitations for SEG-144-T003.
- The release package ships the Luau and Lua licenses (`licenses/Luau.txt`, `licenses/Lua.txt`) and names Luau in `THIRD-PARTY-NOTICES.txt`.
- Windows and macOS builds are covered by the existing CI matrix (the library is part of the normal build); the sanitizer job is Linux only.

Rejected: updating Luau's own CMake build (it pulls the targets we exclude); vendoring CodeGen and disabling it (code that cannot run should not be shipped); compiling at install or run time (the build identity must carry the digest); accepting package-supplied bytecode "verified by a signature" (policy section 2).
