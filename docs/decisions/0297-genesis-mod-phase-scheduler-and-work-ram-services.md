# ADR 0297: the Genesis mod phase scheduler, input interception and bounded work-RAM services

- Status: accepted (SEG-138-T001 and SEG-138-T002, combined delivery F08). Implements, for Genesis, the phases, the input rule and the guest-write rules of [ADR 0282](0282-mod-execution-phases.md) / [mod-execution-phases.md](../architecture/mod-execution-phases.md) sections 2 and 4, through the ABI 2 provider table of [ADR 0283](0283-native-sdk-abi-2.md).
- Not in scope (later SEG-138 tasks): function hooks (`hook-entry`/`hook-exit`, T004), callback ordering of several mods, `MODSTATE` in save states and rewind (T006), replay-recording integration and sandbox failure policy beyond the per-callback fault (T007), linking an ABI 2 provider into a built program (T009).

## Decision

1. **One scheduler, in the runtime tree.** `platforms/genesis/runtime/mod_scheduler.{h,c}` (strict C11, library `segarecomp::runtime_genesis_mod`) is the only place phases are driven. A native ABI 2 provider and the Luau adapter are both just `SegaModProvider` tables whose `phase` entry the scheduler calls; the scheduler is the single authority for capability, phase, space, range, alignment, width, budget, staging and commit. A Luau script and a C11 provider therefore get identical results (tested as a matrix against both).
2. **A NULL-by-default seam in the runtime.** `GenesisRuntime::frame_hooks` (three optional function pointers: `start`, `frame_end`, `after_snapshot`) is called only on dispatch boundaries: `start` at the head of `genesis_runtime_run` (idempotent per machine start: `init`, `reset`, then the opening phases of frame 0, all before the first dispatch), `frame_end` at a virtual frame boundary after the instruction retired and **before** the frame is rendered and published, and `after_snapshot` after publication (`render` from copies, then `frame-begin`, `input`, `post-input` of the next frame). Callbacks take zero guest time: the master clock is only ever advanced by `genesis_runtime_retire_m68k_instruction`. The three pointer tests cost one comparison per run slice or per frame, none per dispatch; the library without a scheduler is byte-for-byte what it was (the existing whole-struct `memcmp` determinism tests are unchanged).
3. **Phases implemented:** `reset`, `frame-begin`, `input`, `post-input`, `frame-end`, `render` (frame numbers are the runtime's `virtual_frame_count`; `render(N)` and `frame-end(N)` carry the frame that just ended). A mod registers the phases it uses (a mask); hook phases are refused (`E_PHASE_UNSUPPORTED`) until T004. Attach negotiates ABI, platform, minor and the required capabilities and refuses with the stable classes of native-sdk-abi-2.md section 5 plus `E_PHASE_UNSUPPORTED`, `E_RANGE_DECLARATION`, `E_PROVIDER_ENTRY`, `E_SCHEDULER_BUSY` (one scheduler per runtime; the ABI 2 service functions carry no context pointer, so one is reachable at a time).
4. **Violations are faults, deterministically.** Any capability, phase, space, range, alignment, width/value or budget violation (by a native provider calling a service, or by a Luau binding) makes the *callback* fault: staged writes, staged input and staged log lines are discarded, the mod is disabled for the session, `E_MOD_FAULT cause=<class> mod=<id> phase=<phase> frame=<n>` is written to the host log sink, pad interception ends and the guest continues unmodified. Luau-only failures (error, budget, memory, stack, watchdog) reach the same path through the adapter's fault sink. Service functions always exist (they never return NULL) and answer with the `SegaModStatus`; the fault is the consequence whether or not the provider checks the status.
5. **`render` is read-only.** In `render` every guest-visible mutation (`write`, `input_set`) and `input_get` is `E_PHASE`; the only memory read is of a 64 KiB copy taken after `frame-end`, and only with `frame.work_ram` (a native provider reads it through `host->read`; the grant is the complete 64 KiB frame copy by the ABI 2 catalogue ("copy of the platform's work RAM"), independent of declared ranges - the copy bound, width and alignment still apply, and declared ranges bound the LIVE memory of the other phases. A Luau script gets a deterministic `phase` fault from `sega.mem.read` in `render` whatever capabilities it holds; its render-time view of frame data is `sega.frame.value`). Presentation output (`overlay.rgba`) is collected by the provider adapter (`PhaseProvider::overlay()`), never fed back.
6. **Input interception.** The sample (`pad1`/`pad2`, the physical state the recording stores) is taken once per frame at the frame boundary. `input_set` is legal only in `input` and only with `input.intercept`, button bits 0-255 on port 1 or 2. When a mod registered the `input` phase (and was not disabled), the guest reads the per-frame final state through `mod_pad_active/mod_pad1/mod_pad2` in the controller read path; otherwise it reads the physical pad continuously exactly as before. A run with an `input` mod therefore latches the pad per frame; a mid-frame physical change is seen the next frame (documented; Vanilla and non-`input` mods are unaffected and bit-identical).
7. **Bounded, endian-aware work-RAM services (T002).** Space is an explicit argument (`SEGA_GEN_SPACE_*`; Luau names it: `"m68k.work_ram"`). Only `m68k.work_ram` is accessible; ROM, Z80 RAM and the VDP spaces are named, never writable (`readonly`), and not readable in this version (`space`). Width is in bytes (1, 2, 4), values big-endian as the M68K sees them, `u16`/`u32` must be even (`alignment`), and every access must lie inside one **declared range** whose modes (read/write) match; the manifest's ranges are validated when the scheduler attaches (outside the 64 KiB, empty, no mode, a mode whose capability is not granted: `E_RANGE_DECLARATION`). Writes are **staged** (reads in the same callback see them), limited to 1024 operations and 16384 bytes per callback (`budget`), legal only in `frame-begin`, `post-input` and `frame-end`, and committed atomically in staging order when the callback returns without fault. Every committed write is appended to a bounded diagnostic log (4096 records, overflow counted) AND streamed into a running SHA-256 (frame, phase, space, offset, width, value, then the total count); `genesis_mod_write_log_digest` is that digest, so it is the replay witness for the complete history even after the retained log overflows. Writes of a faulted callback never enter it.
8. **Luau binding.** `libs/luau_host`'s `PhaseProvider` turns a compiled Luau mod into a provider table: callbacks `reset`, `frame_begin`, `input`, `post_input`, `frame_end`, `render` run in the matching phases (the script's defined callbacks become the registered phases), bindings `sega.mem.read/write` (`memory.read|write.m68k.work_ram`) and `sega.input.get/set` (`input.read`, `input.intercept`) are thin copies of the scheduler's services (the Luau API table, `.d.luau` and `api.json` gained them). The binding checks only the argument types; phase, range, alignment and budget are the scheduler's.

## Declared-range provenance (boundary with SEG-138-T009)

`GenesisModConfig::ranges` is the scheduler's input; F08 validates it (inside the space, non-empty, modes backed by granted capabilities) but does **not** derive it from a package: the package-to-scheduler binding is part of linking an ABI 2 mod into a built program, which is SEG-138-T009. A capability alone never authorizes an RAM offset: the scheduler denies every access outside a declared range, so a config without ranges grants no live access. **T009 acceptance requirement:** the production path builds the ranges only from the verified package's per-revision declaration for the exact source-image digest being run, and refuses (fail closed, build time) a package whose declaration is missing, belongs to another revision, is unverified, or names a space/mode the capabilities do not grant. No schema change is needed for this; if the T009 refinement finds the schema 3 revision record cannot carry ranges, that is a bounded harness refinement, not part of F08.

## Consequences

- The existing Luau-only HUD path (ADR 0296) is unchanged: its program still calls `render(frame)` once per presented frame through the ABI 1 HUD seam and grants only `host.log` and `overlay.rgba`; a package requiring a memory or input capability is still refused at build (`E_LIVE_CAPABILITY`). Linking the scheduler and an ABI 2 provider into a built program is SEG-138-T009.
- The Genesis adapter marks the memory and input capabilities `experimental`; this delivery does not raise a support level because no built program uses them yet.
- No-mod overhead: with no scheduler attached the per-dispatch path has no added work. Measured on a synthetic 60-frame run of the optimized runtime (best of 15 runs, 11 alternating runs of each build, same host): pre-change 88.36 ms, with this change 88.69 ms (+0.4 %); individual runs of both varied by about +-5 % on the shared host. The documented tolerance for the no-mod path is 5 %. With a scheduler attached and only `render` registered the same run measured within noise of Vanilla (ratio 0.95-1.06).

## Rejected alternatives

Dispatching from the viewer (frame boundaries are inside `genesis_runtime_run`, and headless runs must behave identically); a second Luau-specific scheduler (the contract demands one capability model and one order); running callbacks in the middle of a slice without `frame_end` before the snapshot (would break the "state the game used" rule of ABI 1); immediate (unstaged) writes (no transactional rollback).

## Verification (F08 final head)

Local, container: `genesis_mod_scheduler_tests`, `luau_phase_scheduler_test`, `luau_api_test`, the mod/Luau suites, `ci_shard_guard_test` pass; with SDL3 enabled `launcher_mod_variant_test`, `genesis_patch_provider_build_test` and `mod_luau_executable_test` (generated-native F07 HUD, custom-driver link, log JSON round trip) pass. The canonical fast gate (242 tests) had three failures that are not caused by this delivery: `segarecomp_build_command_test` (a generated hook file using `fdopen` under `-std=c11`; code untouched here), `m68k_conformance_harness_test` (subprocess killed after 300 s on the shared host), and a wall-clock assertion of `genesis_mod_scheduler_tests` that flaked under load and was removed (timing is evidence only). The authoritative gate is the exact-head CI of PR #224. An independent adversarial review returned VALID (two low-severity limitations, documented below).

## Limitations

- `PhaseProvider::overlay()` holds the last render output the Luau callback produced; a host must present it only while the scheduler reports no fault (`GenesisModScheduler::fault.faulted == 0`), because a violation the scheduler alone detects does not clear it.
- A C++ exception escaping a provider is not handled (the adapter's Luau calls do not throw); the scheduler is single-threaded, one at a time, and `mod_id`/`provider` pointers must outlive it.
- One mod per scheduler; no hook phases; no `MODSTATE`; the pad latch only when an `input` mod is registered.
- `frame.vdp`, `scenery.words` and audio capabilities are not services of this scheduler.
- Evidence is a synthetic hand-written program (the same shape as the runtime's other synthetic tests), not a generated-native program of a built fixture ROM; the end-to-end gameplay example is SEG-138-T009.
