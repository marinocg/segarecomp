# ADR 0293: Guest injection, static validation, collisions, Genesis header repair and deterministic BPS

- Status: accepted (combined delivery F05: SEG-136-T004, SEG-136-T005, SEG-136-T006).
- Builds on: ADR 0292 (assembler), ADR 0290 (edits, verified symbols), ADR 0281/0288 (schema 3 reader, host).

## Decisions

1. **Injection.** Blocks are placed only inside declared free ranges of the same revision. A free range carries its expected fill byte; when an image is built the ORIGINAL bytes of the whole range must all equal the fill (`E_GUEST_RANGE_NOT_FREE`), the range must lie inside the image (`E_GUEST_RANGE`), and a block must lie wholly inside one range (`E_GUEST_OUTSIDE_FREE_RANGE`). The mod therefore never overwrites bytes it has not asserted are padding. Injected bytes enter the image before generated-native recompilation; the recompiler sees an ordinary image (verified by `tests/mod_guest_exec_test.py`, which recompiles an injected synthetic routine and checks the executed state).
2. **Address model per platform** (a table, not heuristics in shared code): Genesis M68K code executes at its cartridge address (offset = address, even, below the 4 MiB window; `at` is refused; beyond the window or an SSF-mapper cartridge is `E_MAPPER_UNSUPPORTED`). Master System Z80 code requires the declared `rom_only` mapper, offset = address below 0xC000; the `sega` bank-switched mapper is `E_MAPPER_UNSUPPORTED` (bank-aware placement is out of scope). Genesis Z80 code runs from sound RAM: `at` (below 0x2000) is mandatory and the bytes are placed at the ROM offset for the 68000 side to copy.
3. **Static validation of the emitted bytes** (`E_GUEST_*`), independent of the mnemonic table: (a) forbidden instructions, decoded from the emitted words - M68K privileged and system opcodes (`reset stop rte trapv illegal trap move-usp movec move to/from sr andi/ori/eori to sr`, line-A/line-F), Z80 `halt di ei im reti retn rst in out ld i/r`; raw `dc.w` in the code stream is validated as an opcode, other raw data must follow a `data` statement; (b) branch targets must be a local label or a verified `@symbol`, never a number (`E_GUEST_BRANCH_TARGET`), with displacement range checks (`E_GUEST_BRANCH_RANGE`); (c) statically-known absolute stores must lie in the platform's declared writable RAM (Genesis work RAM `0xFF0000-0xFFFFFF`; SMS `0xC000-0xDFFF`; Genesis Z80 `0x0000-0x1FFF`), so a mod cannot patch ROM or a device through an absolute address (`E_GUEST_WRITE_OUTSIDE_RAM`). **Limitation:** a store through an address register or (HL) cannot be proven statically; the generated runtime treats the cartridge as immutable (ADR 0280), so such a store cannot change code, but it is not statically bounded.
4. **Collisions are judged per revision** and independent of the other revisions: free ranges must not overlap each other, a ROM edit must not overlap a free range or a block, blocks must not overlap (`E_GUEST_COLLISION`). Adjacent ranges are allowed. They run in the package reader (so `check`/`pack` already fail) and again at build.
5. **Header repair is an explicit declaration** (manifest `header_repair`, `mod.toml` `[build] header_repair`): `genesis-checksum` (strict) sets the ROM-end field (0x1A4) to the image size - 1 and rewrites the checksum (0x18E, the sum of big-endian words from 0x200 to the end, modulo 2^16); it fails closed (`E_HEADER_UNSUPPORTED`) unless the image is even-sized, 0x200 to 4 MiB, with ROM start 0, and `E_MAPPER_UNSUPPORTED` for an SSF cartridge. `none` opts out. Absent: the checksum is rewritten only when the ORIGINAL image fully verifies (ROM end = size - 1, checksum correct) and the build changed the image; an image that never verified is left as it is. Declaring `none` on an original that verifies, when the output no longer verifies, yields the warning class `W_CHECKSUM_NOT_REPAIRED` in `mod apply|bps|pack --rom` output. Images are never resized, so the length fields are checked or corrected, never grown. The declaration is part of the manifest and content digest.
6. **BPS construction** (`patch::build_bps`): one deterministic left-to-right scan; a run of at least 4 positions equal to the source at the same index is one SourceRead, every other position is TargetRead literal (adjacent literals merge); no SourceCopy/TargetCopy, no metadata, canonical variable-length numbers, three CRC-32 values. The writer is only trusted through the strict reader: every build is applied back and compared by digest before it is returned. Deltas are not optimised beyond determinism.
7. **Tooling.** `segarecomp mod apply` writes the verified target image of one declared revision (edits, then injected code, then header repair); `mod bps` writes the BPS and prints source, target and patch digests; `mod verify-bps` refuses a corrupted BPS (`E_BPS_INVALID`) and a BPS that does not produce this mod's target (`E_BPS_STALE`); `mod pack|build --rom <image>` (repeatable) builds, BPS-encodes and round-trips each named image BEFORE the package is written, without changing the package bytes. `effective_image` (variant keys) uses the same build, so install, variant and apply agree.
8. **Not delivered here:** images are never distributed; bank-switched mappers, other platforms' checksums, multiple `guest-asm` payloads per package, indirect-store bounds and code hooks (M05) are out of scope.

## Consequences

- New stable classes (see schema 3 section 9): `E_GUEST_*`, `E_MAPPER_UNSUPPORTED`, `E_HEADER_UNSUPPORTED`, `E_BPS_BUILD`, `E_BPS_INVALID`, `E_BPS_STALE`, warning `W_CHECKSUM_NOT_REPAIRED`.
- A package containing `guest-asm` can no longer coexist with `bps-image`.
