# ADR 0295: the Luau host API, its static check, the state seam and the deterministic fixture session

- Status: accepted (SEG-137-T004..T007, combined delivery F07). Implements [ADR 0284](0284-luau-trust-policy.md) / [luau-trust-policy.md](../architecture/luau-trust-policy.md) sections 3-5 and 8 on top of [ADR 0294](0294-luau-vendoring-vm-and-trusted-compile.md).
- Related: ABI 2 capability catalogue (native-sdk-abi-2.md section 4/7), execution phases (mod-execution-phases.md), ADR 0267 (the fixed HUD overlay path).

## Decision

1. **One API table.** `luau::api_entries()` (`libs/luau_host/src/luau_api.cpp`) is the only list of host names a script can reach: `sega.log` (`host.log`), `sega.frame.value` (`frame.work_ram`), `sega.overlay.rect/text/width/height` (`overlay.rgba`) and the lifecycle callbacks `reset` and `render(frame)`. Every entry names its catalogue capability (no new capability: policy section 7 forbids it without an ABI minor), its phases and its parameter types. The runtime bindings, the static check, the generated `.d.luau` (`segarecomp mod api --declarations`) and the JSON list (`mod api`) are all derived from, or checked against, this table; the committed copies under `docs/product/luau/` are compared by `mod_luau_api_test`, so CI fails on drift.
2. **Bindings are gated by capability, per VM.** `Vm::create(identity, limits, HostConfig)` installs only the bindings whose capability the package declared and the platform supports (`host_config_for`: required plus supported optional). An ungranted name is absent; reaching for it (the compiler resolves simple `sega.a.b` chains when the function is loaded, any other access happens at the call) raises a sticky `capability` fault through the `__index` guard of every `sega` namespace table. Any other missing key is plain nil.
3. **Faults are sticky and transactional.** Argument errors (type, NaN/infinity, fractions, negative or out-of-range, wrong argument count) are `range` faults; calling a binding outside its phase is a `phase` fault; more than 16 log lines or 64 overlay requests per callback is a `budget` fault. A faulted callback discards everything it staged (`Output` is returned only on success). Out-of-bounds overlay geometry is **clamped** and over-long text/log lines are **truncated**, each with a non-fatal note (`overlay_clamped`, `overlay_clipped`, `text_truncated`, `log_truncated`); control and non-ASCII bytes become `?`. The `sega` tables are read-only and return plain numbers, strings and nil: no userdata, no host pointer or address, `getmetatable` answers `"locked"`.
4. **Frame values are copy-in.** The host publishes at most 32 named integers per frame (`FrameInput`); `sega.frame.value(name)` returns a copy or nil. This release publishes them only to the fixture session: the Genesis runtime does not yet publish game values to scripts (see Limitations). No guest-memory read or write exists (M05).
5. **Overlay = the existing fixed HUD overlay path.** Requests are data (`OverlayOp`). `rasterize_overlay` renders them into one 128x256 RGBA8 image (the size of `GENESIS_COMPAT_OVERLAY_MAX_W/H`), source-over, integer arithmetic only, text in the viewer's SDL-free body font (`sv_font.h`, reused by linking `viewer_core`). The image has the form the viewer's overlay seam accepts; connecting it to the live viewer is later work.
6. **Static check = a narrow, deterministic AST check, not type inference.** `mod check`, `mod pack` and `mod build` run `analyze_mod`: it parses each `luau-source` with the vendored parser and flags `E_LUAU_API` (a `sega.*` name that is not in the list), `E_LUAU_CAPABILITY` (a listed name whose capability the manifest does not declare) and `E_LUAU_TYPE` (wrong argument count, a literal of the wrong type, a fractional literal for an integer parameter, `:` instead of `.`, calling a value or a namespace, a callback that declares more parameters than the host passes). Output is `<path>:<line>: <message>` for the first issue plus the full list; nothing is written on failure. It follows direct chains only; an alias (`local s = sega`) is held to the same rules at run time. A file that does not parse is skipped here and reported by the trusted compile step (`E_LUAU_SYNTAX`), so `check` and `pack` keep not compiling. **The Luau Analysis (type inference) module is deliberately not vendored** (it would add roughly a third of the vendored source and a second parser/solver to the trust base for a feature that is advisory); full type checking uses the external `luau-analyze`/`luau-lsp` against the generated declarations, documented in `docs/product/luau-scripting.md`. The policy lint "`pairs` over tables keyed by non-number/non-string values" is **not implemented** (it needs type inference); the runtime stays host-order dependent for such tables and state serialization orders keys canonically.
7. **Editor integration is configuration, not a product.** `mod init --template luau` writes `types/segarecomp.d.luau`, `.luaurc` (strict) and `.vscode/settings.json` (`luau-lsp.types.definitionFiles`). Nothing is shipped or installed. The Genesis template script is the committed SDK example (`platforms/genesis/sdk/examples/luau-hud`); a test keeps them equal. Other platforms get a log-only template (their adapters grant `host.log` only).
8. **State seam.** `Vm::save_state` calls the global `save()` (absent = empty state) and serializes its one result canonically (booleans, finite numbers, strings, tables keyed by numbers or strings; keys ordered numbers-then-strings; depth <= 8; <= 64 KiB; no function, userdata, buffer, NaN, infinity or cycle); `Vm::load_state` parses strictly (truncation, trailing bytes, unknown tags, duplicate or unordered keys, over-depth, NaN, oversize are refused) and calls `load(value)`. Any failure is a `state` fault: the mod is disabled and the caller refuses the whole restore (phases section 6.2). The save-state container (`MODSTATE`) that carries the blob is M05; this is its Luau-side contract and gives the `state-integrity` category something real to test.
9. **Fixture session.** `luau::run_fixture_session` / `segarecomp mod session <dir|package> --rom <image> [--frames N] [--bmp file]` runs a Luau-only package (never native/mixed: `E_TRUST_CLASS`) against a synthetic, ROM-free 320x224 picture seeded by the fixture image digest, published values `score`/`lives`/`timer`, the compiled script (trusted compile child; nothing from the package is loaded as bytecode), the overlay composited at the picture's top-left as the viewer's seam does, and a SHA-256 per frame and per session. A script fault disables only its mod (stable `E_MOD_FAULT cause=... mod=... callback=... frame=...: ...` diagnostic); the host keeps presenting frames. It does **not** run the Genesis machine.
10. **Install consent.** `mod install` prints `approval_kind` (`none` for data, `consent` for Luau-only, `native` for native/mixed) and the install sheet text of policy section 6. A Luau-only package needs no native approval; the launcher's consent UI (SEG-143/SEG-135) shows the same text.
11. **Runtime error taxonomy** (policy 6.1): *syntax* = `E_LUAU_SYNTAX` at build; *runtime* = `error`; *budget* (`budget`, `stack`, `watchdog`), *memory*, *capability*, *range*, *phase*, *state*: `E_MOD_FAULT` with that cause. The cause names are the `Fault` values.

## Consequences

- `mod check`/`pack`/`build` can now fail with `E_LUAU_API`, `E_LUAU_CAPABILITY`, `E_LUAU_TYPE` (new, listed in schema 3 section 9 as host-raised classes). Existing packages whose scripts do not use `sega.*` are unaffected. `init --template luau` for Genesis now declares `host.log`, `frame.work_ram` and `overlay.rgba` and writes a HUD script.
- Because the compiler resolves `sega.x.y` chains when a function is loaded, a script that merely references an ungranted binding faults with `capability` at load, not at the call. This is deterministic and fail-closed; the consequence is that an **optional** capability the platform does not grant cannot be feature-detected by a script in this release (no `sega.has` exists; a later ABI minor may add one).
- Scripts still do not run inside games: the live viewer/runtime wiring, the guest-memory services and the `MODSTATE` container are M05/M07 work.

## Limitations (stated, not hidden)

- The fixture session proves script -> overlay request -> raster -> composite -> frame hash. It is not a Genesis render; the frame hash is of a synthetic picture.
- The static check is best effort; the run-time gates are authoritative.
- Portability: the pipeline is integer-only and the golden session hash is asserted by the same test on every CI platform (Linux, macOS, Windows). Locally it was exercised on Linux aarch64 only.
- `luau-analyze`/`luau-lsp` integration is documented configuration; no CI job installs them, so the external command is not exercised in CI.

Rejected: vendoring Luau Analysis now (size, second solver in the trust base); a new `frame.number` capability (policy forbids capabilities outside the catalogue; the frame number is the callback argument); making rate-limit violations non-fatal (policy section 4 assigns them the `budget` fault class).
