# ADR 0288: Modding platform host side - schema 3 reader, `mod.toml` projects, adapter registry, ABI 2 SDK headers, bounded sources and audio declarations

- Status: accepted (combined delivery F02: SEG-135-T001, SEG-135-T002, SEG-135-T003, SEG-146-T002, SEG-146-T003, SEG-145-T002).
- Implements: ADR 0280 (adapters), ADR 0281 (schema 3), ADR 0283 (ABI 2), ADR 0286 (audio). Related: ADR 0266/0267 (schema 1/2, unchanged).

## Context

F01 fixed the contracts and implemented nothing. F02 turns the parse/validate/pack half into code without executing a payload, without a new runtime and without changing schema 1/2 or the ABI 1 header.

## Decisions

1. **One schema 3 validation path.** `libs/media/src/mod_package.cpp` is the only code that judges a schema 3 package. A `mod.toml` project is converted into a manifest and the canonical package is **re-read through that same reader** before a project is accepted, so a project can never describe something the reader refuses and vice versa. The packer emits only the canonical form (section 2 of the schema); the reader accepts any valid ZIP layout.
2. **Shared archive code, schema-specific policy.** The ZIP/DEFLATE/closed-JSON reader moved verbatim from `patch_package.cpp` into the internal `patch_archive.cpp`, parameterised by a policy struct (entry count, per-entry and total limits, a deflate ratio cap, name rule, JSON limits). Schema 1/2 keeps exactly its former limits and names through a legacy policy; its tests, pinned identities and error texts are unchanged.
3. **Stable classes everywhere.** Every rejection is `{class, message}`; the classes are the table of schema 3 section 9 plus the build-time classes of ABI 2 section 5, and two added by this delivery: `E_INCLUDE_FORBIDDEN` (source include policy) and `E_COMPILE_FAILED` (host compile of a package unit). Declared audio mailboxes use the space classes of the adapter contract (`E_SPACE_READONLY`, `E_SPACE_UNKNOWN`, `E_ACCESS_RANGE`, `E_ACCESS_ALIGNMENT`).
4. **Strictness choices left open by the contract.** The reader refuses insignificant whitespace in the manifest (identity is the hash of the exact bytes; the canonical form has none) and requires the `role` field the table lists. A `native-c11` payload without `author`/`abi` is `E_TRUST_UNDECLARED` before any other payload field is judged (this is what schema 3 test vector B requires). Archive paths are lower-case; because of that a case-folded duplicate can only arise from a name the path rule already refuses, and both mechanisms are tested. A deflated entry may expand to at most 256x its compressed size (plus 4 KiB): the zip-bomb ratio.
5. **The platform adapter is a table, not a hierarchy.** `libs/media/src/mod_adapter.cpp` holds the capability catalogue (ABI 2 ids) and, per platform, a support level using the vocabulary of the support matrix. Genesis keeps its four ABI 1 names `supported-with-limitations` and declares the ABI 2 services `experimental` (their runtime is M05); `hook.function` and `audio.host.play` are `unsupported` everywhere (gated). Master System and Sega CD register `host.log` as `experimental` (lifecycle and capability reporting) and everything else `unsupported`, so a package that needs more is refused with `E_CAPABILITY_UNSUPPORTED`, never ignored. Unknown platforms are `E_PLATFORM_UNKNOWN`; there is no inference.
6. **`mod.toml` is a closed TOML subset**: tables, arrays of tables, strings (`\"` and `\\` escapes only), non-negative integers, single-line string arrays. Unknown tables and keys are errors; no key can express a command, URL, flag or absolute path; source paths obey the package path rule and are read without following links; sources are size-limited per kind before they are hashed. The manifest is derived from fields and file bytes only.
7. **ABI 2 headers.** The platform-neutral core is `platforms/sdk/segarecomp_mod.h`; each platform has one header with its typed feature table (`platforms/genesis/sdk/segarecomp_mod_genesis.h`, `platforms/master-system/sdk/segarecomp_mod_sms.h`, `platforms/sega-cd/sdk/segarecomp_mod_scd.h`). `platforms/genesis/sdk/segarecomp_genesis_patch.h` (ABI 1) is untouched. The core carries the load-time negotiation function (`sega_mod_negotiate`) and its stable class names, so the host and the tests share one definition. The host passes `-DSEGA_MOD_TARGET_PLATFORM` and `-DSEGA_MOD_TARGET_ABI_MAJOR`; a header compiled against the wrong target stops with the stable class in its `#error` text.
8. **Native sources are checked textually and compiled by the host.** The include policy is conservative (any `#` directive anywhere is scanned, digraphs/trigraphs are refused, only SDK headers, `<stdint.h>`, `<stddef.h>` and package paths are allowed). `segarecomp mod build` compiles every `.c` unit in path order with host-owned strict C11 flags and the SDK/package include directories only. This delivery does **not** link an ABI 2 provider into a Patched program: the runtime services and phase dispatch are SEG-138; the existing ABI 1 build/link path is unchanged and still the only one linked.
9. **Audio.** Audio assets are `asset` payloads (`audio`: canonical 44-byte-header `wav-pcm-s16le`; `data`: an opaque token-labelled blob for music sequences, instruments and SFX definitions). The *intended use* and the exact-revision binding live in `asset-binding` mappings, extended additively with `use` (`music-sequence`, `instrument`, `sfx`, `pcm-sample`, `enhanced-soundtrack`), an optional `revision` label, an optional site (`offset`+`length`), `bank` and `track`; `command`/`event` mailboxes are validated against the platform space tables. A package with audio assets must state its `license`. The one product conversion is the deterministic reference `u8-mono` (channel average floored, then `(s + 32768) >> 8`); the Master System adapter provides none (PSG only). No game audio format is interpreted.

## Consequences

Consumers (SEG-136 edits, SEG-137 Luau, SEG-138 runtime, SEG-141 sets, SEG-147/148 platforms) build on a single reader and a single manifest model. Linking ABI 2 providers, running scripts and applying edits remain later work. The additive audio mapping fields are recorded in the schema 3 and audio architecture documents.

Rejected alternatives: a second hand-written manifest writer outside the reader's validation (two truths); a polymorphic adapter class hierarchy; compiling with package-supplied flags; accepting a lenient manifest and normalising it (identity ambiguity).
