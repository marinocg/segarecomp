# ADR 0302: honest geometry declarations, per-scene and per-component coverage, and a repeatable aspect matrix

- Status: accepted (combined delivery F13: SEG-139-T004, SEG-139-T006). Builds on [ADR 0301](0301-widescreen-geometry-rational-aspect-planner-and-bounded-surfaces.md) (the planner and bounded surfaces), [ADR 0267](0267-seg-124-native-widescreen-compatibility-provider.md) (providers) and the schema 3 reservation of the `geometry` key ([segapatch-schema-3.md](../architecture/segapatch-schema-3.md)).
- Presentation only: nothing here reaches guest state, the native picture or a save state.
- Not in scope: a launcher/menu surface for the report, Master System and Sega CD coverage (SEG-147-T009, SEG-148-T010), declaring scenes automatically, any title-specific table.

## Decision 1: a package declares a range and per-scene components; the declaration is a claim, not a grant

Schema 3 `geometry` (and `mod.toml` `[geometry]` + `[[scene]]`) gains `aspect_max`, optional `aspect_min` (default 4:3) and `scenes: [{id, components}]` with components from `actors`, `hud`, `scenery`. The rules are in the schema document; the essentials are: canonical `N:M` ratios inside 4:3..32:9, `min <= max`, scenes need `aspect_max` (a coverage claim without a supported range claims nothing checkable), at most 32 scenes, tokens and strict ordering so a manifest has one spelling. `{"scenes":[]}` stays legal and means "no claim", so every existing package keeps its bytes and identity. The declaration is in the **package identity** (a different claim is a different package) and **not** in the content digest (it is metadata about presentation; two packages with the same payloads still share a build). A declaration never widens what the host does: it can only restrict (Decision 3) and be compared (Decision 2).

It reaches the viewer as one compact text, `min=N:M;max=N:M;scene=ID:comp+comp` (at most 2048 characters; the longest legal declaration, 32 scenes with 32-character ids and all components, is 1,884), produced by `geometry_declaration_text` from the same verified manifest and read by `sv_geomdecl_parse` (pure C in `sv_layout.c`). **Binding:** `segarecomp build --luau-package` (the normal verified build) writes the text into the program's compile (`-DSEGARECOMP_GEOMETRY_DECLARATION` for `viewer_sdl3.c`) and records it in `status.json` (`luau.geometry_declaration`); a changed declaration is a different package identity, so a tampered package is refused by the existing identity check. A compiled-in declaration cannot be loosened by the environment; only a program built without one reads the development variable `SEGARECOMP_PATCH_GEOMETRY`, and the launcher clears it for every launch. The text is parsed once at open; an unreadable text **fails closed** (every frame is outside the range, the diagnostic says the declaration is invalid) instead of being ignored.

## Decision 2: the host measures declared versus delivered, per scene and component

For every extended frame the host accounts, per scene (declared ones, then the unscoped scene `*`) and per component, one of `covered` (declared, inside the range, delivered), `missing` (declared, inside, not delivered), `undeclared` (delivered, never declared: not support), or `outside_range`. **Only what the host accepted counts as delivered**: a surface that fails the host's checks (sequence, geometry, pitch, size) or was produced above the requested level delivers nothing, and a frame whose surface is not even offered for this frame is not accounted. `scenery` = an accepted surface with provenance AUTHORED and a side; `hud` = a frame overlay the host can draw; `actors` = an accepted AUTHORED surface produced at Level 3, i.e. the provider's own claim that the margins carry actors, never inferred from the hardware sprites of a generic extension or from background pixels. Delivery is still observation of what was offered and accepted, not proof that the content is correct or playable. The scene is named through `sv_host_set_scene` by the adapter, never inferred; an unknown or unset scene is accounted in `*` where nothing is declared, so it can only ever be `undeclared`. This keeps the non-goal: **background coverage is never reported as gameplay support**.

The requested aspect compared with the range is exact: 4:3 while Widescreen Mode is Original (it asks for no extension, so a saved ratio is not a request), else the saved exact ratio when set, else the legacy width as the rational `(300 + width) / 225` (so width 100 is exactly 16:9 and the comparison needs no tolerance).

The report is stable JSON (`sv_cov_report_json`; schema string `segarecomp.geometry-coverage/1`; fixed key order, integers only, declared scenes in order then `*`, `last_aspect`, `last_status`), asserted byte for byte in `sv_coverage_test`. The Genesis viewer writes it to `SEGARECOMP_COVERAGE_REPORT` when it closes. Counters saturate; the report is bounded (at most 33 scenes x 3 components).

## Decision 3: outside the declared range only the native picture is shown, visibly

When the requested aspect is outside the declared range (or the declaration is invalid) the host presents only the native picture: the provider's extension surface and its relocated HUD are not shown, and a toast says `Geometry: outside declared range <min>-<max>, native picture only`, once on entering the state (not every frame). The first design kept a "generic" extension, but an adversarial review showed the surface mixes the provider's own columns and the Raw side style passes them through untouched, so dropping the provider provenance was not enough; nothing a provider supplied is shown. The user's generic Level 2/3 extension is therefore not offered at an aspect the package declared it does not support (a package that wants it simply declares a wider range). A package with no declaration is unrestricted and reported `declared:false` (behaviour unchanged for every existing package). A provider declaring 16:9 and shown at 32:9 reports `outside declared range` (`sv_geometry_decl_test`, also under Raw).

## Decision 4: the aspect matrix is synthetic in CI and aggregate on real games

`sv_widescreen_matrix_test` plans, produces and presents one fictional scene at 4:3, 16:9, 21:9 and 32:9 through the shared host in an integer 2x window (a pixel replication, independent of renderer filtering). Each row's composed output is compared with an independent construction **and** a committed golden hash; coverage uses a fictional provider declaring `max=21:9`, so the rows are `pass`, `pass`, `pass`, `partial` (32:9 is correct but shows the native picture only); host time has a coarse absolute budget; surface memory is checked against the single fixed allocation. `genesis_extension_test` gains a coarse producer budget per aspect and a guard against super-linear growth. The table, deltas against 16:9, limitations and the local real-game runbook are in [widescreen-aspect-matrix.md](../architecture/widescreen-aspect-matrix.md). Real-game results are aggregate numbers recorded only in the private harness (never frames, captures or traces); this repository never claims support the synthetic evidence does not show.

## Decision 5: the aspect is selectable and the diagnostics are visible

The in-game Video page gains **Widescreen Aspect** (Slider / 4:3 / 16:9 / 21:9 / 32:9, plus a read-only Custom for a hand-edited ratio) directly below Widescreen Width, and the launcher's Video settings gain the same row; Slider clears the ratio so the legacy width applies again, and the width's hint says when it is not in use. A package's declaration shows as one sentence under the item (`sv_host_geometry_note`): the supported range, what was delivered so far, or that only the native picture is shown at the requested aspect. The ratio stays a global setting (ADR 0301 decision 4).

## Consequences

- No behaviour changes without a declaration; a declaration can only make the host more conservative.
- Today the verified binding reaches the **Luau HUD mod** build path (the only schema 3 path that builds into a viewer program); `hud` is therefore the component a built program can deliver. Native schema 3 providers are not linked yet, and schema 2 patch packages have no `geometry` field (they keep `widescreen_width_max`, read-only), so scenery/actors coverage cannot yet be observed in a shipped program.
- **Scene observation is not solved here.** Nothing in the Luau API or in provider ABI 1 reports a scene, and the host must not infer one; frames therefore account in the unscoped scene `*` and per-scene `covered` is reachable only through `sv_host_set_scene` by a platform adapter (exercised by the unit tests). A genuine route (for example a guest-state-derived scene id from an ABI 2 provider, or a Luau `sega.scene` call whose value is itself a declared claim) needs its own task and is deliberately not invented here; it is the refinement this delivery hands off.
- The launcher has no mod-package UI yet, so it only clears the development variable and exposes the aspect setting; the declaration sentence is shown by the in-game Video page.
- The coverage report has no file/CLI surface besides `SEGARECOMP_COVERAGE_REPORT` (written at close; sized for 32 scenes).
